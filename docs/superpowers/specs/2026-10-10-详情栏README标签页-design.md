## 2. 关键约束

### 2.1 打开一个仓库，不应该向外部发任何请求

这是整个设计的出发点。这个软件平时不联网：状态是本地读，联网的只有一个明确标着
「联网检查更新」的动作。README 里最常见的元素是徽章图片
（`[![CI](https://img.shields.io/ci.svg)](...)`），渲染成 `<img>` 就是几十个第三方请求，
还顺带把 IP 和仓库名递出去——而用户点开某个仓库时并没有预期这件事。

**规则：`img` 一律不加载远程资源。** 带 alt 的渲染成那个文字，没 alt 的留一块灰底占位。
链接不自动请求；点不点由用户，而点开才发请求——那是主动行为，与自动请求不是一回事。

### 2.2 两类安全问题要分开答

`react-markdown` 默认不碰 `dangerouslySetInnerHTML`，**执行安全基本是白送的**；
但它**不保证网络访问安全**，那部分库压根不在关注范围内。两类都要有钉死的用例（见 §6）。

| 类别 | 威胁 | 谁负责 |
|---|---|---|
| 执行安全 | 恶意 HTML、`<script>`、`javascript:` 协议链接 | 库（不装 `rehype-raw`）+ 我们的 `urlTransform` |
| 网络访问安全 | 图片 / 链接偷偷请求第三方、碰到本机敏感资源 | **完全由我们** |

### 2.3 `urlTransform` 是唯一那个闸门

所有会变成 URL 的东西——图片、`a href`、GFM 的自动链接（裸 URL）——都从 `urlTransform`
过。不在各个 `components` 覆写里各写一遍协议判断：漏一处就是一个洞，而漏的那处
恰好是最难发现的（自动链接不长得像链接）。

| 元素 | 放行 | 拦下 |
|---|---|---|
| `img src` | `data:image/*`（内联图，不联网） | `http(s):`、`file:`、相对路径 |
| `a href` | `http:` `https:` `mailto:` | `javascript:` `data:` `file:`（Tauri webview 里 `file:` 能碰到本机文件）、相对路径 |

被拦下的**不是变成一个空链接**：链接渲染成不可点的普通文字，图片渲染成 alt 文字或灰底占位。
一个点了没反应的蓝链接比一个普通文字更让人困惑——前者看起来像个能点的东西。

### 2.4 「没有 README」与「读不出来」必须分开

照抄 `/projects/:id/log` 那条注释里的规矩（空仓库给空列表、失败要报出去）：

- 是仓库但没有 README → **200**，`file: null`。没有 README 是正常状态，不是错误。
- 目录没了 / 不是仓库 → **400**，带人话。
- README 是二进制 → 换下一个候选名；全都不行 → 当作「没有」。

判据用 HEAD 解不解得出来那条同样的逻辑：这里没有 HEAD 可用，所以用「候选文件里
有没有一个是能当文本读的」。

### 2.5 「没有按钮」优于「点了也没用的按钮」

README 超过**完整加载上限**（1MB）时，底部渐变里**不给按钮**，直接写
「这个 README 有 40 MB，太大了，没法在这里显示」。

一个点了之后还是被截断的按钮是死控件，而这个项目一直把死控件当 bug 治
（过滤面板里那个点不动的「未分类」就是这么改掉的）。

## 3. 数据层

### 3.1 `readReadme`（core，放 `packages/core/src/git/readme.ts`）

```ts
export interface ReadmeResult {
  /** 命中的文件名，例如 'README.md'；没有可读的就 null */
  file: string | null
  /** 读到的正文；没有可读的就 null。可能是截断后的一段 */
  content: string | null
  /** 真被截断了吗（不是「上限内的完整」） */
  truncated: boolean
  /** 文件真实大小（字节）——界面上要如实显示 xx MB */
  bytes: number
}

export async function readReadme(dir: string, opts?: { maxBytes?: number }): Promise<ReadmeResult>
```

流程：

1. 目录不存在 → **throw**（调用方转 400）
2. 按候选名依次试：`README.md` / `readme.md` / `README.MD` / `README` / `README.txt`
   - 不是文件 → 试下一个
   - 是二进制 → 试下一个
   - 读到 → 返回
3. 全部候选都不行 → `{ file: null, content: null, truncated: false, bytes: 0 }`

`truncated` 只有一个取值，界面判断「要不要显示加载完整按钮」靠它就够了——不需要再带一个
「实际给了多少字节」的字段，两个都能回答同一个问题的字段迟早会不一致。

**候选名沿用 `scan.ts` 里已经在用的那一份**（`README_NAMES`），把它提出来共享，
不另立一套——同一个仓库有两个地方各认一组文件名，早晚漂。

**截断**：超过 `maxBytes` 就读前 `maxBytes` 字节并 `truncated: true`。
注意别照抄 `scan.ts` 的处理：那里超限是 `continue`（当作没有），
那对取 60 字摘要是对的（2MB 的 README 为 60 个字不值得读），
对全文展示是错的——用户要看的就是全文，静默当作「没有」是骗人。

**二进制判据**：读前 4KB 里 U+FFFD（utf8 解码失败的替换字符）超过 1% 就当二进制。
不引入 `is-binary-file` 之类的依赖，三行就够，而这一挡是挡住一屏看不懂的东西。

**不落库**（不变量 12）。

### 3.2 接口

```
GET /api/projects/:id/readme          → 首屏，上限 64KB
GET /api/projects/:id/readme?full=1   → 全文，上限 1MB
```

两种都返回同一个形状：

```ts
{
  file: string | null
  content: string | null
  truncated: boolean
  bytes: number
}
```

错误：目录没了 / 不是仓库 → `400`，消息照 `/log` 的写法（「目录不在了」/「这个目录不是 git 仓库」）。

路径从库里取（`requirePath`），**不接受来自请求的路径**——这是跨站闸与路径约束的一部分。

### 3.3 两个数，和它们各自的职责

| | 建议值 | 它管什么 |
|---|---|---|
| 首屏 | **64 KB** | 第一次渲染多少。约 1500–2000 行，正经的说明文档读不完这一段 |
| 完整 | **1 MB** | 「加载完整文档」按钮的硬上限 |

两个数**都要实测校准**：造一个真的大 README，在浏览器里量 `react-markdown` 的渲染耗时
再定稿，不靠估。它们是孤立的常量，改一行的事。

首屏从 256KB 降到 64KB 的原因：64KB 才是「先给你看多少」，而 256KB 加上「加载完整」之后
就变成了一个没有理由的坎——用户点了按钮还是会被拦在一个自己不知道存在的上限前面。

## 4. 界面

### 4.1 标签页

- 原生 ARIA tabs：`tablist` / `tab` / `tabpanel`，`aria-selected`、`aria-controls`、`aria-labelledby`
- 左右方向键切换，Home / End 跳首尾，Tab 键从标签栏进到内容区
- 选中态用**蓝**（不变量：蓝 = 你能点的 / 当前选中的）
- **切换标签不改 URL**：「正在看哪个项目」住在 URL 里（`/projects/:id`，不变量见
  `ProjectsPage.tsx` 注释），「看它的哪一页」是这一次看的局部状态。换项目时页面重挂载，
  自然回到概览——这正是该有的行为。
- **「加入清单于」留在标签栏外面**：它说的是这个项目，不是这一页。

### 4.2 README 渲染

`react-markdown` + `remark-gfm`（表格、删除线、任务列表、自动链接）。

排版（详情栏只有约 470px 宽，字号不能大）：

| 元素 | 规格 |
|---|---|
| h1 | 17px / 600 |
| h2 | 15px / 600 |
| h3 及以下 | 14px / 600 |
| 正文 | 13.5px / 行高 1.7 |
| 行内代码 | 等宽，`bg-sunken`，`rounded-[3px]` |
| 代码块 | 等宽，`bg-sunken`，横向滚动（不换行——换行会把缩进结构毁掉） |
| 表格 | `overflow-x: auto`，不压缩列（470px 里挤三列只会全糊） |
| 引用块 | 左边线 + `text-ink-2` |

对比度 ≥ 4.5:1（`index.css` 里那张实测表，新配的颜色要重新量）。

### 4.3 渐变与按钮

```
┌ 渐变：linear-gradient(to bottom, transparent, var(--color-bg))，高约 5rem
│ ┌──────────────────────────┐
│ │  加载完整文档（1.2 MB）   │ ← 居中浮在渐变上；ghost 按钮
│ └──────────────────────────┘
```

- **只在 `truncated === true` 时出现**。没被截断的 README 连渐变都不该有
- 文案里的 MB 从 `bytes` 来，实测值如实显示，不四舍五入成「1 MB」
- 点击 → 再请求一次（`?full=1`）→ 成功则把 `content` 换掉，渐变与按钮一起消失，
  内容直接接上；**不需要分页**，≤1MB 的文件点一次就到底了
- 点击期间按钮上写「正在读…」，禁重复点击
- `bytes > 1MB` → 不给按钮，渐变位置写「这个 README 有 40 MB，太大了，没法在这里显示」
- 加载完整失败 → 保留渐变，按钮变回可点，下面挂一条错误提示说清原因（不能一声不响）

## 5. 视觉系统

不引入新颜色。README 用的是既有 token：`bg-bg` / `text-ink` / `text-ink-2` / `text-ink-3` /
`bg-sunken` / `border-line` / `text-accent`。标签栏的选中态用蓝，与清单里选中行同一套。

灰底占位（无 alt 的图片）：`bg-sunken` + 固定高度 2rem + `border-line`，
**不留「图片加载失败」那种破图标**——它会让人以为网络有问题，而我们已经决定不发请求了。

## 6. 测试

### 6.1 安全性质（这一轮最该被钉住的东西）

按**性质**写，不按组件写。web 层：

| 用例 | 断言 |
|---|---|
| `[点我](javascript:alert(1))` | 渲染出来没有 `href`，是个不可点的元素 |
| `[点我](file:///C:/Users/x/secret)` | 同上，被拦 |
| `[装订](./docs/install.md)` | 不可点的普通文字（我们不显示仓库里其它文件） |
| `![](https://evil.example/pixel.gif)` | 渲染出来**没有 `src`** |
| `<script>alert(1)</script>` 写在 README 里 | 不是真实节点 |
| 裸 URL（GFM 自动链接）`https://x.com` | 生成的 `a` 也带 `target="_blank" rel="noreferrer noopener"` |

最后一条不是测「自动链接会不会被拦」——GFM 的自动链接只认 `http/https/email`，
`javascript:` 压根不会被它变成 `<a>`，那个分支不存在。真正要钉的是**自动链接产生的
链接和手写的链接走同一条策略**：它不长得像链接，`components.a` 那条路走起来也不显眼，
最容易在加策略时被忘掉。

`javascript:` / `file:` 那两条要写成**显式 markdown 链接** `[文字](javascript:alert(1))`，
那才是真正的攻击面。

### 6.2 core 层 `readReadme`

五种结果各一条：找到 / 没有 / 超限截断（`truncated` 为真且 `bytes` 是**真实**大小）/
是二进制（换候选名，全不行则当没有）/ 目录不存在（throw）。

### 6.3 路由层

有 README 200、无 README 200（`file: null`）、不是仓库 400。
`?full=1` 的上限比默认大，且上限以内的 `truncated` 为假。

### 6.4 标签页

默认落在概览；左右方向键能切；`role` 与 `aria-*` 齐全；切换不改 URL。

### 6.5 会被这次改动打破的现有用例

`ProjectDetailPage` 相关用例会多出标签栏，断言文案时要限定到概览页内。
逐个改，不改断言的语义。

### 6.6 不测

- `react-markdown` 自己的渲染正确性（库的活）
- 渐变的视觉效果（截图人工过）
- 真实大 README 的渲染耗时（**实测时人工量一次**，量完把数写进本文件 §3.3）

## 8. Review Focus

下面几条最可能咬人，而它们只有靠测试才看得见：

1. **一个 README 里满是 `javascript:` 链接的仓库** —— 渲染出来必须一个能点的都没有。
   这条一旦破了，README 就是一个从第三方仓库执行任意脚本的入口。
2. **一个 README 里全是远程徽章的仓库** —— 打开它，DevTools 的 Network 面板必须是空的。
3. **一个 2MB 的 README** —— 点「加载完整文档」之后界面还能用（不能白屏）。
   反过来：一个 40MB 的 README，渐变处**没有按钮**。
4. **一个只有 `readme.txt` 的仓库** —— README 页要显示得出来（候选名不能只认 `.md`）。
5. **一个 README 是 GBK 编码的中文仓库** —— 渲染出来不能是一屏乱码；
   判据要么认出来当「不是文本」，要么给一个说得清的提示，不许装成读到了。
