# 清单界面重整（第一轮）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 清单页从「九列表格 + 三段过滤」变成「六列表格 + 四段侧栏 + 蓝色体系」，并把「行动分类」这一判定一次性收到服务端，让列表显示、状态筛选、侧栏计数三者不可能漂移。

**Architecture:** `attention`（可更新 / 已同步 / 不推荐 / 待检查 / 需要确认）不是 `projects` 表的一列，它在 `update_checks.detail` 的 JSON 里，且「哪次检查算数」有 `MAX(id) WHERE status IN (REMOTE_CHECK_STATUSES)` 这层规则。判定写成一段 SQL 表达式，随列表与详情返回；前端只渲染不重算。视觉上换掉整套 token：白底 + 蓝主色，层次靠明度差与发丝线，蓝色只表示「你能点的」，四色只表示「git 事实」。

**Tech Stack:** TypeScript · Fastify + better-sqlite3（服务端）· React 19 + Vite + Tailwind v4 + TanStack Query + zustand（前端）· Vitest + msw + testing-library

**Spec:** `docs/superpowers/specs/2026-10-09-清单界面重整-design.md`

## Global Constraints

- **不改任何数据库结构。** `attention` 是查询期算出来的，不加列（STATUS.md 不变量 14：开发期不做数据迁移）。
- **分类时间无关，措辞时间相关。** 分类可筛选；「上次看是最新」那类降级只改措辞与颜色（不变量 5），两者分层，筛选不许随时间漂。
- **`attention` 的服务端实现是唯一一份。** 前端出现任何「按 verdict 判断该显示什么分类」的代码都是 bug。
- **每一对前景/背景颜色对比度 ≥ 4.5:1。** 11.5px 的元信息**不算大字号**，按正文算。
- **蓝色不出现在「状态」与「同步状态」两列里。** 蓝 = 你能点的 / 当前选中的；四色 = git 事实。
- **只有「可更新」是绿的。** 已同步 / 待检查 / 需要确认都是灰或琥珀。
- **四个筛选维度各自独立、叠加。** 分类与标签可以同时开着（现状如此，别改）。
- **不写裸 emoji 当图标。** 用 `lucide-react` 的 inline SVG。
- **不碰：分页、详情标签页、标签增删改入口、拖拽调宽、打开目录类按钮。**
- 提交信息用中文，conventional 前缀（`feat:` / `fix:` / `refactor:` / `test:` / `docs:`）。

## Review Focus

下面五条来自「人会怎么用这个软件」，它们最可能咬人，而设计文档只写了「要做什么」、没逐条钉住：

1. **断网后点一次检查** —— 失败的那次不该把「上次看是最新」的绿色「已是最新」刷新出来（不变量 9）。分类必须仍是 `unchecked`，不能变成 `synced`。
2. **一个项目同时勾了「可更新」筛选项、又在别人把它推到 `blocked` 之后才看列表** —— 状态筛选必须立刻反映，不给过期缓存。
3. **清单栏被拖窄** —— 收列断点按清单栏宽度算，不按窗口宽度（不变量 16）；状态列要先于差异列被收掉，理由要说清。
4. **一个仓库先 `diverged` 后来被推平成 `safe`** —— `MAX(id)` 取的是最新的**合格**检查，中间那次不合格的不能污染分类。
5. **`personal` 分类的旧数据还在库里** —— 分类枚举改成不含 `personal` 之后，读旧行不能崩，显示成原样字符串即可（`categoryLabel` 的兜底）。

每条在下面都有对应的测试步骤钉住。

/**
 * 「这个仓库现在该不该动」——从**最近一次真正问到远程结论**的那次检查推出来的。
 *
 * **分类时间无关**（可筛选），而「上次看是最新」那类措辞降级是**时间相关**

- [ ] **Step 5: server 加 SQL 片段**

`apps/server/src/repos/projects.ts`，在 `toProject` 之前插入：

```ts
/**
 * 「哪次检查算数」在 SQL 里的写法，和 `latestChecksByProject` 同一个口径：
 * 只有 `REMOTE_CHECK_STATUSES` 里的状态才算（fetch 失败的、不是仓库/没远程的
 * 都不算——否则断网后点一次检查，界面会显示刚确认过的绿色「已是最新」）。
 *
 * 字面量内联而不是绑成 `?`：REMOTE_CHECK_STATUSES 是本文件 import 的编译期
 * 常量（不是用户输入），而这段片段要在 JOIN 子查询里复用，按位置绑参容易错位。
 */
const QUALIFIED_STATUS_IN = `(${REMOTE_CHECK_STATUSES.map((s) => `'${s}'`).join(', ')})`

/** 逐项目带出「最近一次合格检查」 */
const LATEST_CHECK_JOIN = `
  LEFT JOIN update_checks c ON c.id = (
    SELECT MAX(id) FROM update_checks
    WHERE project_id = p.id AND status IN ${QUALIFIED_STATUS_IN}
  )
`

/**
 * `attention` 的判定。与 `recommendationFromDetail` 读的是同一个 `detail`。
 *
 * 用 `canPull` 而不是 `behind > 0` 判「可更新」：detail 里专门存了 canPull，
 * 注释写着「光凭 verdict 推不出来——『已是最新』也是 safe，但没东西可拉」。
 */
const ATTENTION_SQL = `
  CASE
    WHEN c.id IS NULL THEN 'unchecked'
    WHEN json_extract(c.detail, '$.verdict') IN ('rewritten', 'unrelated') THEN 'blocked'
    WHEN json_extract(c.detail, '$.verdict') = 'diverged' THEN 'decide'
    WHEN json_extract(c.detail, '$.canPull') = 1 THEN 'ready'
    WHEN json_extract(c.detail, '$.verdict') = 'safe' THEN 'synced'
    ELSE 'unchecked'
  END
`
```

在 import 里补 `REMOTE_CHECK_STATUSES`（若尚未导入）。

const ATTENTION_TEXT: Record<Attention, string> = {
  ready: '可更新',
  synced: '已同步',
  blocked: '不推荐',
  decide: '需要确认',
  unchecked: '待检查',
}

const ATTENTION_CLASS: Record<Attention, string> = {
  ready: 'bg-ok-bg text-ok',
  synced: 'bg-flat-bg text-flat',
  blocked: 'bg-bad-bg text-bad',
  decide: 'bg-amber-bg text-amber',
  unchecked: 'bg-amber-bg text-amber',
}

/** 「该动吗」。读服务端给的 attention，前端不重算。 */
export function AttentionBadge({ attention }: { attention: Attention }) {
  return (
    <span
      className={`inline-flex items-center rounded-full border border-transparent px-2 py-[3px] text-[11.5px] font-medium ${ATTENTION_CLASS[attention]}`}
    >
      {ATTENTION_TEXT[attention]}
    </span>
  )
}

/** 「跟远程差多少」。**刻意全用中性灰**——它是上下文，不是行动项。 */
export function SyncBadge({
  ahead, behind, upstreamGone, hasCheck,
}: {
  ahead: number | null
  behind: number | null
  upstreamGone: boolean
  hasCheck: boolean
}) {
  const text = !hasCheck
    ? '未知'
    : upstreamGone
      ? '上游已关闭'
      : ahead! > 0 && behind! > 0
        ? '已分叉'
        : behind! > 0
          ? '远程领先'
          : ahead! > 0
            ? '本地领先'
            : '一致'
  return (
    <span className="inline-flex items-center rounded-full border border-transparent bg-flat-bg px-2 py-[3px] text-[11.5px] text-flat">
      {text}
    </span>
  )
}

/** 两个方向都给：↑ 本地领先 / ↓ 远程领先 */
export function Delta({ ahead, behind }: { ahead: number | null; behind: number | null }) {
  return (
    <span className="font-mono text-[12px]">
      {behind! > 0 ? <span className="text-ok">↓{behind}</span> : <span className="text-ink-3">↓0</span>}
      {' '}
      {ahead! > 0 ? <span className="text-amber">↑{ahead}</span> : <span className="text-ink-3">↑0</span>}
    </span>
  )
}

旧的「落后」列走 `StatusCell` 的 `textFor`，超过 12 小时会把「已是最新」降级成

```tsx
export const STALE_AFTER_MS = 12 * 60 * 60 * 1000

export function AttentionBadge({ attention, checkedAt }: { attention: Attention; checkedAt: string | null }) {
  // 分类不变（筛选还按它），只有**措辞**降级——这是 2.4 那条边界
  const stale = checkedAt !== null && Date.now() - new Date(checkedAt).getTime() > STALE_AFTER_MS
  const text = stale ? `上次看是${ATTENTION_TEXT[attention]}` : ATTENTION_TEXT[attention]
  return <span className={`… ${ATTENTION_CLASS[attention]}`}>{text}</span>
}
```
