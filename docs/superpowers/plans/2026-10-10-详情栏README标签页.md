# 详情栏 README 标签页 · 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 详情栏从一条竖直内容流变成「概览 / README」两页，README 用 markdown 渲染，且**打开一个仓库不向外部发任何请求**。

**Architecture:** core 新增 `readReadme`（找、读、截断、判二进制），路由 `GET /api/projects/:id/readme` 默认给前 64KB、`?full=1` 给前 1MB。web 端所有会变成 URL 的东西经 `urlTransform` 过同一个 `readmeUrl` 闸门——执行安全靠库（不装 `rehype-raw`），网络访问安全靠自己写。超限时底部渐变 + 「加载完整文档（xx MB）」按钮；超过完整上限则**不给按钮**。

**Tech Stack:** TypeScript · Fastify + better-sqlite3 · React 19 + Vite + Tailwind v4 + TanStack Query · `react-markdown` + `remark-gfm`（本轮新增）· Vitest + msw + testing-library

**Spec:** `docs/superpowers/specs/2026-10-10-详情栏README标签页-design.md`

## Global Constraints

- **打开一个仓库不向外部发任何请求。** `img` 一律不加载远程资源（徽章尤其）。
- **执行安全靠库，网络访问安全靠自己。** 不装 `rehype-raw`；`urlTransform` 是唯一那个闸门。
- **`img` 只放行 `data:image/*`；`a` 放行 `http: https: mailto:`。** 其余（含 `javascript:` `data:` `file:` 与一切相对路径）一律拦下，**渲染成不可点的普通文字**，不是一个空链接。
- **「没有 README」是 200 + `file: null`；「目录没了 / 不是仓库」才是 400。** 两者必须分开。
- **超过完整加载上限（1MB）时不给按钮**，渐变处写明真实大小。不给点了也没用的死控件。
- **README 只读、不落库、不缓存。** 界面上没有任何改它的入口（不变量 13、12）。
- **不引入新颜色。** 只用既有 token：`bg-bg` `text-ink` `text-ink-2` `text-ink-3` `bg-sunken` `border-line` `text-accent`。
- **每一对前景/背景对比度 ≥ 4.5:1。**
- **不碰不变量 1 / 2 / 4 / 9 / 10。** 本轮不新增任何后台行为，命令日志不变。
- **测试一律从仓库根目录跑并带路径过滤**：`pnpm vitest run <仓库相对路径>`。root vitest 配置的 projects 是仓库相对路径，从子目录跑会解析错位。
- **提交信息用中文**，conventional 前缀（`feat:` / `fix:` / `refactor:` / `test:` / `docs:`）。

## Review Focus

这五条最可能咬人，而设计文档只说了「要做什么」、没逐条钉住。每条都在下面的任务里有对应的测试步骤。

1. **一个 README 里全是 `[点我](javascript:alert(1))` 的仓库** —— 渲染出来必须一个能点的都没有。破了这道，README 就是从第三方仓库执行任意脚本的入口。→ Task 4 Step 1
2. **一个 README 里全是远程徽章的仓库** —— 打开它，DevTools 的 Network 面板里**不能有任何一条来自图片的请求**。→ Task 4 Step 1
3. **一个 2MB 的 README** —— 点「加载完整文档」之后界面还能用，不能白屏；反过来，一个 40MB 的 README 渐变处**没有按钮**。→ Task 5 Step 8（人工实测）+ Task 4 Step 1（按钮出现与否的两条断言）
4. **一个只有 `readme.txt` 的仓库** —— README 页要显示得出来。候选名不能只认 `.md`。→ Task 1 Step 1
5. **一个 README 是非 utf8 编码的中文仓库** —— 渲染出来不能是一屏乱码；要么被认出来是二进制、要么给一句说得清的提示，不许装成读到了。→ Task 1 Step 1

- [ ] **Step 4: 建 `packages/core/src/git/readme.ts`**

```ts
import fs from 'node:fs'
import path from 'node:path'
import { README_MAX_BYTES } from '../limits.ts'

/**
 * 候选名。**原来只有 `scan.ts` 私有一份**，现在提出来两边共用：
 * 同一个仓库有两个地方各认一组文件名，早晚会漂（扫描时说「没有说明」，
 * 详情页却读出来了）。
 */
export const README_NAMES = ['README.md', 'readme.md', 'README.MD', 'README', 'README.txt'] as const

export interface ReadmeResult {
  /** 命中的文件名，例如 'README.md'；没有可读的就 null。**不是路径**——路径不出本机。 */
  file: string | null
  /** 读到的正文；没有可读的就 null。可能是截断后的一段。 */
  content: string | null
  /** 真被截断了吗（「上限内的完整」不是截断） */
  truncated: boolean
  /** 文件真实大小（字节）——界面上要如实显示 xx MB */
  bytes: number
}

/**
 * 读仓库根目录的 README。
 *
 * **不落库、不缓存**（不变量 12：能从仓库自己读出来的不存）。每次现读——
 * README 是会变的，缓存一份就等于给用户看一个可能过期的说明。
 *
 * 五种结果必须分得开，混起来的后果都是「界面在说一件不成立的事」：
 * - 读到 → `{ file, content, truncated, bytes }`
 * - 目录不存在 → **throw**，由调用方转 400
 * - 是仓库但没有可读的候选名 → `{ file: null, content: null, truncated: false, bytes: 0 }`
 * - 太大 → 读前 `maxBytes` 字节，`truncated: true`，`bytes` 是**真实**大小
 * - 候选名是二进制 → 试下一个；全都不行 → 当作「没有」
 */
export async function readReadme(
  dir: string,
  opts: { maxBytes?: number } = {},
): Promise<ReadmeResult> {
  const maxBytes = opts.maxBytes ?? README_MAX_BYTES

  // 目录在不在由这里判一次，不靠「每个候选名 stat 都失败」来推断：
  // 那样「目录没了」和「目录在但没有 README」会长得一模一样。
  const dirStat = await fs.promises.stat(dir).catch(() => null)
  if (!dirStat?.isDirectory()) throw new Error(`目录不在了：${dir}`)

  for (const name of README_NAMES) {
    const file = path.join(dir, name)
    const stat = await fs.promises.stat(file).catch(() => null)
    if (!stat?.isFile()) continue

    const truncated = stat.size > maxBytes
    const text = (
      truncated ? await readPrefix(file, maxBytes) : await fs.promises.readFile(file)
    ).toString('utf8')

    if (looksBinary(text)) continue
    return { file: name, content: text, truncated, bytes: stat.size }
  }

  return { file: null, content: null, truncated: false, bytes: 0 }
}

/**
 * 读前 `maxBytes` 字节。**按字节切而不是按字符切**：`fs.read` 给的是字节，
 * 在多字节字符中间断开会让末尾那几个字变成替换字符。
 *
 * （断开点仍然可能落在一个多字节字符里，于是末尾有一两个替换字符——
 * 那是截断处该有的样子，底部的「加载完整」按钮就是给它准备的。）
 */
async function readPrefix(file: string, maxBytes: number): Promise<Buffer> {
  const handle = await fs.promises.open(file, 'r')
  try {
    const buf = Buffer.alloc(maxBytes)
    const { bytesRead } = await handle.read(buf, 0, maxBytes, 0)
    return buf.subarray(0, bytesRead)
  } finally {
    await handle.close()
  }
}

/**
 * 前 4KB 里 utf8 解码失败的替换字符超过 1% → 当二进制。
 *
 * 不引 `is-binary-file` 之类的依赖，三行就够，而这一挡拦住的是「一屏看不懂的
 * 东西」：PNG 被改名成 README.md、GBK 编码的中文说明——渲染出来用户无从读起，
 * 而界面会说「这是它的说明」。
 */
function looksBinary(text: string): boolean {
  const probe = text.slice(0, 4096)
  if (probe.length === 0) return false
  let bad = 0
  for (const ch of probe) if (ch === '�') bad += 1
  return bad / probe.length > 0.01
}
```

新建 `apps/web/src/features/readme/urlPolicy.ts`：

```ts
/**
 * README 里会变成 URL 的东西只有两类，而两类**放行的协议不同**。
 *
 * 这一整个设计的安全前提是这个软件**打开一个仓库不向外部发任何请求**：
 * README 里最常见的是徽章图片（`[![CI](https://img.shields.io/…)]`），
 * 渲染成 `<img>` 就是几十个第三方请求，还顺带把 IP 和仓库名递出去，
 * 而用户点开某个仓库时并没有预期这件事。
 *
 * 一个函数两个 `kind`，而不是散在各个组件里各判一次：散开就会出现
 * 「链接拦了、图片忘了」这种洞，而图片那条洞恰好最不容易发现——
 * 因为它不报错，只是安静地往外发请求。
 */
export type ReadmeUrlKind = 'image' | 'link'

/**
 * 图片只放行内联的 `data:image/*`。
 *
 * `data:image/svg+xml` 也在这一档里，而它在 `<img>` 里是安全的：
 * img 上下文不执行脚本，也不加载外部资源。（放进 `data:` 链接里才危险，
 * 而 `data:` 压根不在链接那一档。）
 */
const IMAGE_ALLOWED = ['data:image/']

/** 链接放行这三种，且一律 `target="_blank" rel="noreferrer noopener"`。 */
const LINK_ALLOWED = ['http:', 'https:', 'mailto:']

/**
 * 放行返回原值，拦下返回**空串**。
 *
 * 返回空串而不是原值：空串让下游知道「这个不可用」，好把它渲染成普通文字；
 * 返回原值则会被照常渲染成那个链接——那才是洞。
 */
export function readmeUrl(url: string, kind: ReadmeUrlKind): string {
  const value = url.trim()
  // 没有 scheme 就是相对路径（或页内锚点），一律不放行。
  // 仓库里那些文件我们不显示，可点的就是一个死链接。
  if (!/^[a-z][a-z0-9+.-]*:/i.test(value)) return ''

  const lower = value.toLowerCase()
  const allowed = kind === 'image' ? IMAGE_ALLOWED : LINK_ALLOWED
  return allowed.some((p) => lower.startsWith(p)) ? value : ''
}
```

```ts
import { useQuery } from '@tanstack/react-query'
import { api } from '@/lib/api'
import { queryKeys } from '@/features/projects/queries'

/**
 * wire 上的形状，**照抄服务端返回的四个字段**。
 *
 * 故意不从 `@git-nest/core/git` 引 `ReadmeResult`：那个入口带 node:child_process，
 * 浏览器侧一碰就炸（core/index.ts 顶部那段注释就是在说这件事）。
 */
export interface ReadmeData {
  /** 命中的文件名；没有可读的就 null。**不是路径**——路径不出本机。 */
  file: string | null
  content: string | null
  /** 真被截断了吗（「上限内的完整」不是截断） */
  truncated: boolean
  /** 文件真实大小（字节）——按钮上要如实显示 */
  bytes: number
}

/**
 * `full` 进 query key，所以「加载完整文档」就是换一条查询：
 * 首屏那条不动，完整那条单独缓存，切回概览再回来也不用重新读盘。
 */
export function useReadme(projectId: number, full: boolean) {
  return useQuery({
    queryKey: queryKeys.readme(projectId, full),
    queryFn: () => api.get<ReadmeData>(`/projects/${projectId}/readme${full ? '?full=1' : ''}`),
  })
}
```

- [ ] **Step 7: `ReadmeView.tsx`**

新建 `apps/web/src/features/readme/ReadmeView.tsx`：

```tsx
import { useState } from 'react'
import Markdown from 'react-markdown'
import remarkGfm from 'remark-gfm'
import { Button, ErrorNote } from '@/components/ui'
import { ApiError } from '@/lib/api'
import { formatBytes } from '@/lib/format'
import { README_FULL_MAX_BYTES } from '@git-nest/core'
import { readmeUrl } from './urlPolicy'
import { useReadme } from './queries'

const reason = (e: unknown, fallback: string) => (e instanceof ApiError ? e.message : fallback)

/**
 * README 的渲染。
 *
 * 两条不变量：
 * 1. **打开它不向外部发任何请求。** 策略全在 `urlTransform` 里（`readmeUrl`），
 *    渲染出来的兜底是「不可点的普通文字 / alt 文字 / 灰底占位」，
 *    而不是留一个点了没反应或加载不出来的元素。
 * 2. **读不出来与没有是两回事**，界面上说的话不一样。
 *
 * **两条查询而不是一条**：首屏那条负责「有没有 / 读没读得出来」，
 * 完整那条只负责「加载完整」这一个动作的结果。用一条的话，「加载完整」一失败
 * 整页就变成错误页——用户刚读到一半，渐变和按钮全没了，连重试的地方都没有。
 * 现在失败时 `whole.data` 是 undefined，于是内容退回首屏那份，渐变与按钮原样留着。
 */
export function ReadmeView({ projectId }: { projectId: number }) {
  const [full, setFull] = useState(false)
  const initial = useReadme(projectId, false)
  const whole = useReadme(projectId, full)

  if (initial.isPending) {
    return <p className="py-6 font-mono text-[12.5px] text-ink-3">正在读 README…</p>
  }
  // 400 是服务端说了原因的（「目录不在了」/「不是仓库」），照着显示，不自己编
  if (initial.isError) {
    return <ErrorNote message={reason(initial.error, '读不到 README')} />
  }
  const first = initial.data
  if (!first || first.file === null) {
    return (
      <p className="text-[12.5px] text-ink-3">
        这个仓库没有 README——想留点什么，在「编辑资料」的「记录」里写一段。
      </p>
    )
  }

  // 完整那条还没回来、或失败了，就用首屏那份继续渲染
  const data = (full ? whole.data : null) ?? first
  const bytes = data.bytes
  const truncated = data.truncated
  // 超过完整上限还给按钮，点下去还是被截断——那是死控件。直接说清有多大。
  const tooBig = bytes > README_FULL_MAX_BYTES

  return (
    <div className="text-[12.5px] text-ink-3">
      <p className="mb-2 font-mono">
        {data.file} · {formatBytes(bytes)}
      </p>

      <div className="readme">
        <Markdown
          remarkPlugins={[remarkGfm]}
          /*
            **唯一那个闸门。** 拦下的 URL 变成空串，下面的 components 看到
            `href === ''` 就渲染成普通文字——不是留一个点了没反应的蓝链接。
            （图片与链接放行的协议不同，`node.tagName` 就是要区分的那一位。）
          */
          urlTransform={(url, _key, node) =>
            readmeUrl(url, node?.tagName === 'img' ? 'image' : 'link')
          }
          components={{
            a: ({ href, children }) =>
              href ? (
                <a href={href} target="_blank" rel="noreferrer noopener">
                  {children}
                </a>
              ) : (
                // 不可点的普通文字：文字还在，只是不再假装能点
                <span>{children}</span>
              ),
            img: ({ src, alt }) => {
              if (!src) {
                return alt ? (
                  <span className="readme-badge">{alt}</span>
                ) : (
                  <span className="readme-img-placeholder" aria-hidden />
                )
              }
              // 这里只会是 data:image/*，不联网
              return <img src={src} alt={alt ?? ''} />
            },
          }}
        >
          {data.content ?? ''}
        </Markdown>
      </div>

      {/*
        渐变只在**真被截断**时出现。40KB 的 README 连渐变都不该有——
        那一块存在的唯一理由是「后面还有东西，而这里给不了」。
      */}
      {truncated ? (
        <div className="readme-more">
          <div className="readme-more-inner">
            {tooBig ? (
              <p>这个 README 有 {formatBytes(bytes)}，太大了，没法在这里显示。</p>
            ) : (
              <Button
                disabled={whole.isFetching}
                // 已经切到完整那条了就变成重试，不用再改 state
                onClick={() => (full ? whole.refetch() : setFull(true))}
              >
                {whole.isFetching ? '正在读…' : `加载完整文档（${formatBytes(bytes)}）`}
              </Button>
            )}
          </div>
        </div>
      ) : null}

      {/*
        「加载完整」失败要说出来。渐变与按钮**留着**（上面 data 回退到了首屏那份），
        下面挂一条原因——一声不响地把按钮变回可点，用户只会以为刚才那次已经加载完了。
      */}
      {full && whole.isError ? (
        <div className="mt-2">
          <ErrorNote message={`完整版没读出来：${reason(whole.error, '再点一次试试')}`} />
        </div>
      ) : null}
    </div>
  )
}
```

配套说明：`ReadmeView` 里那个 `useReadme(projectId, full)` **不需要 `enabled`**。
`full` 还是 `false` 时，它与 `useReadme(projectId, false)` 是同一个 query key，
React Query 自己会去重（同一棵树、同一个 key = 一次请求）；`full` 变成 `true` 之后
key 变了，才真的多发那一次 `?full=1`。

`apps/web/src/lib/format.ts` 末尾追加（该文件现在只有 `formatDate` / `formatRelative` /
`shortenPath` 三个函数，没有现成的可复用）：

```ts
/** 字节 → 人读的体积。**不四舍五入成整数 MB**：按钮上写着「1 MB」而实际是 1.2 MB，
 *  用户点下去才发现被截断，就晚了。 */
export function formatBytes(n: number): string {
  if (n < 1024) return `${n} B`
  if (n < 1024 * 1024) return `${(n / 1024).toFixed(1)} KB`
  return `${(n / 1024 / 1024).toFixed(1)} MB`
}
```

- [ ] **Step 4: 加标签栏**

在 `ProjectDetailPage.tsx` 里加一个本文件内的小组件：

```tsx
/**
 * 标签栏。
 *
 * **只管「切」，不管内容。** 切换**不改 URL**：「正在看哪个项目」住在 URL 里，
 * 而「看它的哪一页」是这一次看的局部状态。改了 URL 的话浏览器的前进后退就会
 * 开始记录「我翻到第几页」，而那不是一个值得记的动作。换个项目时页面重挂载，
 * 自然回到概览——这正是该有的行为。
 */
function TabBar<T extends string>({ tabs, value, onChange }: {
  tabs: readonly { key: T; label: string }[]
  value: T
  onChange: (v: T) => void
}) {
  const refs = useRef<(HTMLButtonElement | null)[]>([])
  const move = (delta: number) => {
    const at = tabs.findIndex((t) => t.key === value)
    const next = (at + delta + tabs.length) % tabs.length
    const key = tabs[next]!.key
    onChange(key)
    refs.current[next]?.focus()
  }

  return (
    <div role="tablist" className="flex shrink-0 gap-1 border-b border-line px-4">
      {tabs.map((t, i) => (
        <button
          key={t.key}
          role="tab"
          ref={(el) => { refs.current[i] = el }}
          aria-selected={t.key === value}
          aria-controls={`panel-${t.key}`}
          id={`tab-${t.key}`}
          tabIndex={t.key === value ? 0 : -1}
          onClick={() => onChange(t.key)}
          onKeyDown={(e) => {
            if (e.key === 'ArrowRight') { e.preventDefault(); move(1) }
            if (e.key === 'ArrowLeft') { e.preventDefault(); move(-1) }
            if (e.key === 'Home') { e.preventDefault(); onChange(tabs[0]!.key); refs.current[0]?.focus() }
            if (e.key === 'End') { e.preventDefault(); onChange(tabs[tabs.length - 1]!.key); refs.current[refs.current.length - 1]?.focus() }
          }}
          className={`-mb-px cursor-pointer border-b-2 px-2 py-1.5 text-[12.5px] ${
            t.key === value
              ? 'border-accent text-accent-ink'
              : 'border-transparent text-ink-3 hover:text-ink-2'
          }`}
        >
          {t.label}
        </button>
      ))}
    </div>
  )
}
```
