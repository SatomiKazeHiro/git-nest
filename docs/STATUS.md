## 核心不变量（改代码前先确认没破坏）

> 编号别动：代码注释与设计文档里有「见不变量 N」的引用。

1. **绝不自动更新。** 检查只 fetch（不动工作区），更新只由用户勾选后触发，且只 `--ff-only`。
   禁止 `reset --hard` / `clean` / `push` / 任何历史重写。
   **更新前还要先比一次基线**（fetch → 比「上次见到的上游 SHA」→ 才动工作区）：
   否则「检查」到「点更新」之间作者 force push 的话，本地 HEAD 仍是新历史的祖先，
   `--ff-only` 会安静快进到一个被改写的仓库。
2. **git 实时状态不落库**，每次现查（server 侧 3 秒短缓存，`?fresh=true` 绕开）。
   落库的下次打开就是旧数据，反而更危险。
3. **同仓库串行、跨仓库并发上限 4**；`Scheduler.schedule` 对同一 key 不可重入。
   所有 git 调用统一走 `runner.ts`（`-C` 而不是 cwd、超时、凭证、命令日志都在那一处）。
   排队 key 会归一（斜杠、Windows 上抹大小写）——同一个仓库的不同写法必须落同一个 key。
4. **勾选判据是判决的 `canPull`，不是 `status === 'behind'`。** 作者 force push
   （`rewritten`）或删库重建（`unrelated`）时，本地 refs 看到的**恰恰就是** `behind`。
   这道闸前后端各一道：前端禁勾只是建议，`runApply` 会再读 `update_checks.detail` 里的判决，
   是「别拉」就跳过（且不写新的检查行——那一步没读到任何新事实）。
   **两处读的必须是同一批行**（`REMOTE_CHECK_STATUSES` 里最新的一条）：服务端原来读
   「最新一行」，而自动 fetch 断网时写的那行没有 verdict，中间插一行闸就凭空松了。
5. **状态措辞按新鲜度降级**：状态接口不联网，「已是最新」在没依据时是失真的。
   从没查过 → 「没查过远程」且不给颜色；>12h → 「上次看是最新」；纯本地状态不受影响。
6. **本地绝对路径只存本机 SQLite**，不进任何会被提交的文件。
7. **core 有两个入口**：`@git-nest/core`（类型+zod，浏览器安全）、
   `@git-nest/core/git`（依赖 node:child_process，只能 node 侧引）。
   在 barrel 里 `export *` git 层会让浏览器包直接白屏。
   同理，`isomorphic-git` 只允许在 `src/git/inspect/via-lib.ts` 里引。
8. **列表页与详情页不共用状态缓存**。列表页走 lean 档，`dirty` 恒为 false、
   `lastCommit` 恒为 null；详情页与 `pull` 的前置检查走 full 档。混用会让详情页在几秒内
   谎报「干净」——而脏标记是第 1 条那个安全闸的判据。
9. **「推不推荐更新」只在真正问过远程之后才算**，而且结论**要落库**
   （`update_checks.detail` 里的 `verdict`）。清单页那条列读的是**上次检查的结论**，
   不是现算的——现算要先 fetch，而列表是纯本地读。没查过就显示「没查过」，
   绝不给绿色的「可更新」。
10. **判「作者改写历史」必须靠基线**（上次见到的上游 SHA）。只看本地 refs 判不出来：
    force push 掉本地从没读过的提交时，本地 HEAD 仍是新历史的祖先，git 自己也会快进。
    基线来自 `update_checks` 里记的、或 fetch 前本地 refs 指的那个。**读基线必须在 fetch 之前**。
    **基线优先用 `fetch` 前本地 refs 指的那个**：SHA 属于某一条上游 ref，而库里不记是
    哪一条——A 分支上记的值拿去问 B 分支必然「不是祖先」，那会变成假警报
    （「作者改写了历史」而作者什么都没干）。库里的值只在本地读不出来时兜底。
11. **自动做的事必须留痕。** 自动 fetch 会自己联网，所以每一条 git 命令都进命令日志
    （`runner.ts` 的 `recentCommands`，带 `label` 标明发起者）。新增任何「自己会跑」的
    后台行为，都要能通过 `GET /api/commands` 查到。
    所以写接口另有一道**跨站闸**（带 `Origin` 且不在白名单 → 403）：`DELETE /api/commands`
    这类接口若能被随便一个网页调到，这条留痕就白留了。
12. **元数据只有一条线：能从仓库自己读出来的不存，只有用户知道的才存。**
    摘要是前者（README 现场读，只有扫描预览里出现、不落库），记录是后者
    （`projects.record` **一个文本框**，链接写在正文里）。不要因为「结构化更整齐」
    再拆出 notes 表、来源链接列、`kind` 字段那一类东西——那三样已经因为同一个原因撤过一次。
13. **一个编辑器，不是两个门。** 项目的可写字段（名称/路径/分类/标签/记录）全部只在
    「编辑资料」弹窗里改；页面各处只做展示与只读渲染（记录在详情页只读，正文里的 URL
    渲染成可点链接）。别再往页面或标签行旁边挂「快捷编辑」按钮——那不是捷径，是第二个入口，
    已经因此返工两次。
14. **开发期不做数据迁移。** 改结构＝直接改 `migrations.ts` 的 `001_init` + 删掉
    `data/git-nest.db*` 重建；**不写** ALTER / DROP 那类「照顾旧库」的步骤（写过一条 004，
    专门删 001 里的两列，还得造假库去测它）。加**新表**可以按 id 追加一条；改**已有表**的
    结构就是改 001 + 删库。旧库不会被就地升级——拿旧库启动会直接报 `no such column`，删库即可。
15. **窗口不滚，滚的是栏。** 根节点锁死不滚，纵向空间由标题栏 / 菜单栏 / 主体 /
    状态栏四条带占掉，滚动只发生在某一栏内部。所以**别再往页面里加 `sticky` 顶栏**——
    那是「文档滚动」时代的做法，它的偏移量必然对不上（表头那个 `top-[3.25rem]`
    就是这么来的：量出来的表头高度，工具条一改行高就悄悄失效）。要固定的东西
    就占掉一整行 grid 轨道，让滚动发生在下面那个区域里。
16. **收列的断点问容器，不问视口。** 三栏之后「窗口多宽」和「表格有多宽」没有任何
    关系了：窗口拖宽、清单栏照样可以很窄。所以 `.col-*` 的收起条件必须是
    `@container`（基准是 `.list-scroll`），不能用 `@media`——用错了不会报错，
    只会让某几列在某几档窗口宽度下被压成「D:/…/…」那种断头话。
17. **快捷键只有一份来源，且会主动让位。** 组合键表在 `lib/keys.ts`、行为经
    `lib/commands.ts` 的注册表，菜单栏与键盘走同一条路（所以菜单上印的与实际
    生效的不可能漂）。三条让位规则少一条就会咬人：**浮层开着要让位**（否则在更新
    报告弹窗里按 Ctrl+A，被全选的是背后那张清单）、**输入框里要让位**（Ctrl+A 在
    文本框里必须还是选中文字）、**没人接手的组合键不拦**（否则浏览器自己的
    Ctrl+R / Ctrl+W 被这个应用悄悄吃掉）。
18. **「右栏在看谁」与「勾选了谁」是两件事。** 前者住在 URL（`/projects/:id`），
    后者住在 store 的 `selected`。混进同一个集合的话，点开一个项目就会把它算进
    「已选」，接着点「联网检查更新」就带上了一个用户没勾过的项目。
    同理，**第 8 条的 lean / full 两档在详情栏常驻之后更容易被「顺手统一」**——
    两处一直共用一条缓存的话，详情页会在几秒内谎报「干净」。`Workspace.status-profile.test.ts`
    用「两个端点返回不同数字」把它钉住。
19. **侧栏与过滤面板是两样东西，不能合回去。**
    - 活动栏（48px 图标栏）：里面**每一项都是一个页面**，点它换一页。
      「清单」只是其中一项，将来加页面就是加一个图标。
    - 过滤面板（`features/projects/FilterPanel.tsx`）：**清单页自己的控件**，
      点了只筛眼前这张表。**只在清单页存在**（`Workspace` 就是清单页的布局路由，
      这是结构保证的）；设置页那一栏只有活动栏，筛选没有对象可筛。
    混在一列里的坏处很具体：「分类」长得像个能点过去的页面，点了却什么都不换。
    另外那条 `index.css` 里 `.nav` 的 `grid-template-rows: minmax(0,1fr)` 不能删：
    **grid 的行会撑满、flex 的子元素不会**，删了里面的 `<nav>` 就按内容高度收缩，
    「设置」会被顶到「清单」下面（踩过两次，见 index.css 的注释）。

20. **「是不是我自己的」是布尔，分类是枚举，两件事互不相关。**
    - `projects.is_own`（勾选框）决定批量检查跳不跳过。它**曾经**是「分类正好等于
      `personal`」——一条挂在自由文本上的隐藏规则，写成 `Personal` 或多打空格就
      静默失效，界面上没有任何提示。
    - `category` 现在是枚举（`CATEGORY_VALUES`：空串 + 四个值），**不带任何行为**，
      只管分组与筛选。`personal` 已移除——留着会诱导人把同一件事记在一个不起作用
      的地方。
    - **「未分类」不是分类，是「没有分类」**：过滤面板里不列它（点它筛不出东西），
      编辑弹窗里也不列它（列了会被预选中，看起来像「你选了未分类」，其实只是
      什么都没选）。两处都是**开关语义**：点一下选中，再点一下取消。
    - 加一个分类 = 改 `types.ts` 的 `CATEGORIES` 一个常量。

## 待用户决定的事

> 这一节按**业务**写：每条都是「什么时候会撞上、撞上是什么样、有什么选择」。
> 实现层面的取舍在别处（不变量第 19、20 条，README 的窗口骨架一节）。

### 1. 窗口不够宽的时候，现在会挤

同时显示四块：左边的图标栏、分类与标签、清单、详情。**要在 1440 的屏幕上左边开
编辑器、右边开这个应用，可用宽度只剩约 700px**——清单会被压到看不清列，详情栏
占掉半个窗口。

三个选择：(a) 就这样，窄的时候自己关掉详情栏（`Ctrl+J`）；(b) 让左边的分类栏
也能收起来；(c) 打包时把最小宽度从 1150 提到 1300 以上（代价是更多屏幕根本
装不下这个应用）。

**默认按 (a) 走**——本轮没做窄窗口降级，是有意的取舍不是漏了。

### 2. 左边几条栏的宽度是写死的

分类名长一点、清单想多看两列，都只能改代码。**要不要让你能拖着调宽窄**？拖完之后
这个宽度**要不要记住**（下次打开还在，还是每次都回默认值）。

### 3. 批量检查与更新盖住整个清单

点「联网检查更新」弹出一个宽窗，清单被完全遮住，你只能等它跑完——**看不到哪些
仓库已经查完了、哪些还没开始**。

**要不要改成停靠面板**（清单还在旁边，能看着它一条条查完）？还是弹窗就够用？
这是本轮明确划出去的范围：它改的是流程而不只是长相。

### 放到后面：打包成桌面软件

窗口控件、图标栏拖拽区、最小宽度、跨站来源白名单都已经就位（README 的
「窗口最小宽度」一节有推导），**等宿主接**。在那之前浏览器里开发是完整的。

### 别的（更远期的）

- **提交图**要不要回到界面上：一阶段撤掉了（`@tomplum/react-git-log` 不虚拟化，
  120 条提交就渲染出成百上千个节点）。后端接口 `GET /api/projects/:id/log` 与
  core 的 `getLog` **保留着**。要显示得先解决虚拟化，别直接塞回详情页。
- **`update_checks` 的历史目前只存不用**（每项目最近 2000 条，约 40 天），
  现在只当「推不推荐更新」的基线与结论载体。想看长期趋势要先调大保留策略。
- **Agent 接入**（设计文档第 10 节）：本来就说本期不做。

## 这个环境独有的坑

（git 行为、依赖安装那些坑都写在 `README.md` 的「踩过的坑」里，这里不重复。）

1. **别用 Windows PowerShell 的 `Invoke-RestMethod` 验中文接口**：它会把 body 里的非 ASCII
   编成 `?`（U+003F），看起来像服务端丢字。验中文往返用 node 的 `fetch`（或 `curl.exe`），
   并且拿**码点**比而不是看控制台输出（渲染也会骗人）：`[...s].map(c => c.codePointAt(0))`。
   同理，用 pwsh 的 `Get-Content` 读中文源码会显示成 GBK 乱码（文件本身没问题）——
   看文件内容一律用读文件的工具。这两条我都据此报过假警报。
2. 用 heredoc 跑 `python - <<'EOF'` 改仓库里的文件**会静默失败**（不报错也没写进去）。
   改文件一律用编辑/写文件的工具。
3. **删开发库 `data/git-nest.db*` 之前先停掉自己的 dev server**：库被它占着会报
   「being used by another process」。按端口找 PID 停（`netstat -ano | grep :5174`）——
   注意 IPv6（`[::1]:5174`）上可能还挂着一个残留实例。vite 现在配了 `strictPort`：
   5173 被占会直接报错退出；以前它会悄悄换到 5174（API 的端口）把 API 撞死，
   而日志里「web ready」和「server EADDRINUSE」并排出现，看起来像一切正常。
4. 验证 UI 用 `playwright-cli`（`open` / `snapshot` / `find` / `screenshot`）；起服务前先删
   `apps/web/node_modules/.vite`，否则改完组件会白屏（报 "does not provide an export named ..."）。
5. msw 3.x 里 `server.listen` 的选项叫 `onUnhandledFrame`（2.x 是 `onUnhandledRequest`）。
6. 写中文文件偶尔混进 U+FFFD 坏字符：提交前跑 `pnpm check:encoding`，比肉眼可靠。
7. `pnpm install` 偶尔「假装 up-to-date」什么都不做，删 `node_modules/.modules.yaml` 也没用；
   全量 `rm -rf node_modules && pnpm install` 才行（store 有硬链接，很快）。

## 测试怎么组织（只留看不出来的）

- git 集成测试全部用临时目录里的**真实仓库**，不 mock git。造仓库很慢（Windows 上每条 git
  命令几百毫秒），所以 core 与 server 都把超时放宽到 60s（core 在 `vitest.config.ts`，
  server 在各测试文件里 `vi.setConfig`）。全量约 40–60 秒。
- web 侧用 msw，且 `onUnhandledFrame: 'error'`——没 mock 的请求必须失败，免得出现
  「测试通过但压根没打到接口」的假绿。
- `apps/server/test/docs-api-drift.test.ts` 拿文档里写的 API 端点与 `GIT_NEST_*` 变量和源码
  对账：改路由却忘了改文档会红。
