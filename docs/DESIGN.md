# Git Nest — Design Reference

> Git Nest 是一个面向本地 Git 仓库的桌面管理工具。界面优先帮助用户快速回答三个问题：有哪些仓库、哪些仓库值得关注、选中的仓库发生了什么。
>
> 本文记录概念图中的视觉语言、布局、组件和交互约定，作为后续 React/Vue 前端实现与 Tauri 迁移的参考。它是设计基线，不是不可变的像素规范。

## 1. 设计原则

- **桌面优先**：围绕宽屏窗口设计，充分利用列表与详情并排的空间。
- **信息密度适中**：支持约 30–200 个仓库；优先紧凑列表，而不是大卡片墙。
- **详情常驻**：始终保留右侧仓库详情，减少页面跳转和上下文丢失。
- **状态优先**：更新建议、检查状态和 Git 同步状态要清晰可辨。
- **低干扰**：大面积使用中性背景；强调色用于当前选择、主要操作和状态。
- **可恢复**：扫描、Fetch、README 读取等操作需要明确的加载、成功、空数据和失败状态。
- **安全默认**：README 是不可信内容；本地路径解析、外部链接和图片加载都应受控。

## 2. 整体窗口布局

### 2.1 三栏工作台

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Git Nest / 本地仓库管理                               窗口控制            │
├──────────────────────────────────────────────────────────────────────────┤
│ 搜索名称、路径、远程地址…                   扫描目录   检查更新            │
├──────────────┬────────────────────────────┬─────────────────────────────┤
│ 左侧导航      │ 仓库列表                    │ 仓库详情                     │
│              │                            │                             │
│ 全部仓库      │ 名称 / 分支 / 状态 / 差异    │ 仓库名、路径、状态             │
│ 可更新        │                            │ 概览 / README / 提交 / 资料    │
│ 已同步        │ 紧凑行、筛选、排序、多选      │ 标签内容独立滚动               │
│ 不推荐        │                            │                             │
│ 待检查        │                            │                             │
│ 标签/分类     │                            │                             │
│ 设置          │                            │                             │
└──────────────┴────────────────────────────┴─────────────────────────────┘
```

### 2.2 尺寸建议

以约 `1411 × 986 px` 的概念图窗口为参考。以下是起始值，布局应可拖动调整并保存用户偏好。

| 区域 | 建议尺寸 | 说明 |
|---|---:|---|
| 左侧导航 | `160–190 px` | 可折叠；状态入口和分类/标签分组 |
| 仓库列表 | 窗口宽度约 `38%–45%` | 设置合理最小宽度，避免名称和状态挤压 |
| 右侧详情 | 窗口宽度约 `55%–62%`（中间区与详情区合计） | 详情常驻，内部标签切换 |
| 顶部应用栏 | `40–48 px` | 应用标识、窗口标题与系统窗口控制 |
| 搜索/操作栏 | `40–48 px` | 搜索、扫描目录、检查更新 |
| 详情标签栏 | `36–44 px` | 概览、README、提交、资料 |

> 分栏比例应根据实际窗口可用宽度计算，不要把所有宽度写死。建议设置每栏最小宽度，并在较窄窗口下允许折叠导航或将部分工具收进菜单。

## 3. 视觉语言

### 3.1 总体风格

- 简洁、克制、偏开发者工具风格。
- 以浅灰、白色和蓝灰色为主，不使用大面积渐变、重阴影或高饱和装饰。
- 主要区域使用细分隔线；圆角集中在按钮、输入框、徽标和少量信息容器。
- 主要信息使用深色文字；次要信息、路径、时间和说明使用灰蓝色。
- 选中状态使用浅蓝灰底色，并配合左侧窄强调线或清晰边框，避免仅靠颜色表达。

### 3.2 颜色令牌（建议起点）

这些是可实现的初始令牌，后续可以按实际概念图和主题微调。

| Token | 建议值 | 用途 |
|---|---|---|
| `--gn-bg` | `#F5F7F9` | 应用主背景 |
| `--gn-surface` | `#FFFFFF` | 列表、详情、输入框等表面 |
| `--gn-surface-muted` | `#EEF2F5` | 列表工作区、次级背景 |
| `--gn-border` | `#D5DDE5` | 分栏线、控件边框 |
| `--gn-text` | `#243142` | 主要文本 |
| `--gn-text-muted` | `#748397` | 次要文本、路径、时间 |
| `--gn-primary` | `#155E75` | 主按钮、选中强调 |
| `--gn-primary-hover` | `#0E4F66` | 主按钮悬停 |
| `--gn-selection` | `#DFEAF1` | 当前选中行背景 |
| `--gn-success` | `#23845B` | 可更新/成功类状态 |
| `--gn-info` | `#3478A8` | 检查中/信息提示 |
| `--gn-warning` | `#B7791F` | 需要确认、风险提示 |
| `--gn-danger` | `#C24141` | 检查失败、不推荐等需关注状态 |

状态色不应成为唯一编码方式；徽标还应有文本和/或图标。深色主题应为这些 token 单独定义映射，不要简单反转颜色。

### 3.3 字体与字号

建议优先使用系统 UI 字体，兼顾中文与英文仓库名：

```css
font-family:
  "Segoe UI",
  "Microsoft YaHei UI",
  "PingFang SC",
  system-ui,
  sans-serif;
```

| 使用场景 | 建议字号 |
|---|---:|
| 应用标题 / 主要详情标题 | `16–18 px` |
| 区域标题 | `14–16 px` |
| 列表仓库名、正文 | `13–14 px` |
| 次要元信息、按钮文字 | `12–13 px` |
| 标签、状态徽标、辅助说明 | `11–12 px` |

正文行高建议为字号的 `1.45–1.65` 倍。仓库名可以稍加粗；路径、哈希和分支名适合使用易读的等宽字体，但不应让所有 UI 文本都变成等宽字体。

### 3.4 间距、边框和圆角

采用 `4 px` 基础间距体系：

- `4 px`：图标与文字间的小间距。
- `8 px`：按钮内部、紧凑列表项间距。
- `12 px`：卡片或面板内部常用间距。
- `16 px`：主要面板内边距。
- `20–24 px`：较大区块之间的间距。

建议：

- 普通输入框/按钮高度：`30–34 px`。
- 紧凑仓库行高度：`40–48 px`。
- 边框：`1 px`，使用中性灰色。
- 常规圆角：`4–6 px`；较大的内容容器最多 `8 px`。
- 分栏边界优先使用直线分隔，不依赖阴影。
- 悬停效果轻微；避免每一行都出现明显卡片阴影。

## 4. 左侧导航

### 4.1 信息结构

推荐按以下顺序组织：

1. 全部仓库
2. 可更新
3. 已同步
4. 不推荐
5. 待检查
6. 分隔线
7. 自定义分类
8. 标签
9. 设置（底部固定）

每个入口可显示仓库计数。计数要和筛选语义一致，并清晰定义是否包含失败或未知状态。

### 4.2 图标规范

状态图标统一使用 `24 × 24` SVG viewBox，UI 显示尺寸通常为 `18–20 px`。采用线性图标、透明背景、统一线宽（约 `1.8 px`）、圆角端点与连接点。

| 入口 | 图标概念 | 建议语义 |
|---|---|---|
| 全部仓库 | 四格网格 | 仓库集合 |
| 可更新 | 圆形向上箭头 | 远程有可拉取的新提交；具体箭头方向可按产品语义统一 |
| 已同步 | 圆形勾选 | 本地与跟踪分支一致 |
| 不推荐 | 圆形叉号 | 根据策略不建议直接更新 |
| 待检查 | 圆形感叹/信息符号 | 尚无有效检查结果 |

图标的线条风格应一致。默认使用中性灰色；选中项跟随导航文字使用主色；状态列表也可使用语义色，但不建议让整个侧栏变成彩色图标墙。

### 4.3 导航项交互

- 高度约 `32–36 px`，左右内边距 `8–10 px`。
- 图标、文字、计数在同一水平线上。
- 当前入口使用浅色背景、主色文字或窄强调线。
- 悬停背景比默认状态略深，过渡时间约 `120–180 ms`。
- 折叠模式保留图标，悬停时提供 tooltip。
- 键盘可聚焦；焦点样式应与选中状态区分。

## 5. 顶部工具栏

### 5.1 搜索框

搜索范围包括仓库名称、本地路径、远程 URL。可以采用即时过滤；输入较慢或仓库数量较大时再增加短防抖。

- 宽度建议 `220–320 px`，允许随窗口增长。
- 占位文案：`搜索名称、路径、远程地址…`
- 支持 `Esc` 清空或关闭建议列表。
- 搜索结果为空时提供清空搜索的快捷操作。
- 后续可增加 `Ctrl/Cmd + K` 全局命令入口，但不要把普通搜索和命令面板混为一谈。

### 5.2 主操作

主操作为“检查更新”，次操作为“扫描目录”。

- 主按钮使用深青蓝色或主题主色。
- 次按钮采用浅背景、细边框。
- 运行中显示进度和禁用重复启动的状态；允许浏览列表。
- 若支持全局批量 Fetch，应显示成功、失败和待处理数量，而不只是一个无限旋转图标。
- 破坏性操作（删除仓库文件、覆盖工作区等）不得放在常规主操作位置。

## 6. 仓库列表

### 6.1 列表原则

- 使用紧凑行，不为每个仓库建立高大的独立卡片。
- 行高建议 `40–48 px`。
- 当前选中行使用浅蓝灰底色，并在左边缘增加细强调线。
- 仓库名优先展示；分支、状态、差异、上次检查时间作为次级信息。
- 路径和远程地址较长时截断显示，并在 tooltip 或详情中提供完整内容。
- 支持按名称、状态、最近检查时间和差异排序。
- 支持多选；多选后在工具栏显示批量操作。
- 对 30–200 个仓库，先用普通列表即可；当实际渲染或滚动性能证明有需要时再启用虚拟列表。

### 6.2 建议列

| 列 | 内容 |
|---|---|
| 仓库 | 名称、必要时附本地路径 |
| 分支 | 当前本地分支；分离 HEAD 需单独表示 |
| 状态 | 可更新、已同步、需确认、不推荐、待检查、检查失败 |
| 差异 | 远程领先/本地领先数量，如 `↓2 ↑1` |
| 上次检查 | 最近成功检查时间；失败尝试可另行提示 |

在较窄窗口下，优先隐藏次要时间列或将其移入详情，不要压缩仓库名称至无法辨认。

### 6.3 状态与推荐结论分离

不能将“检查失败”“远程领先”“不推荐”塞进一个单一状态。它们分别描述检查过程、Git 同步关系和产品建议。详情应展示推荐原因，列表只呈现最有用的摘要。

## 7. 右侧详情面板

### 7.1 面板头部

- 顶部显示仓库名称，必要时提供更多操作菜单。
- 下一行显示完整或可复制的本地路径。
- 远程 URL、当前分支、上游分支、最近检查时间使用次要文本样式。
- 标签放在仓库名称附近的独立区域，避免和状态徽标混成一串。
- 头部与内容区用 `1 px` 分隔线隔开。

### 7.2 固定标签

固定顺序为：

1. **概览**：更新建议、分支关系、检查结果与原因。
2. **README**：Markdown 阅读器。
3. **提交**：本地/远程提交摘要与新增提交。
4. **资料**：本地路径、远程 URL、分类、标签、备注和检查策略。

切换仓库时，默认保留当前详情标签，例如在 README 标签中切换仓库后仍然展示 README。

### 7.3 滚动

- 详情面板头部与标签栏固定。
- 标签内容区独立滚动。
- README 内的目录可在宽度足够时放在内容左侧；较窄时收进目录按钮。
- 不要让整个窗口跟着 README 长文一起滚动。

## 8. README Markdown 阅读器

### 8.1 工具栏

建议包含：

- README 文件名与相对路径。
- 阅读/原文切换。
- 重新加载。
- 更多菜单：复制路径、在文件管理器中显示、在外部编辑器打开。
- 可选显示最近读取时间。

### 8.2 Markdown 内容样式

- 标题有清晰的层级与上下间距。
- 正文行高约 `1.5–1.7`；长行可读宽度建议约 `65–85` 个汉字的视觉宽度。
- 链接使用主题强调色并保留可识别的交互状态。
- 引用块使用浅背景或左侧细边线。
- 表格使用轻量分隔线；宽表格在内容区内部横向滚动。
- 代码块使用中性底色、等宽字体、语言提示和复制按钮。
- 图片保持纵横比，不超过内容宽度；点击可进入独立预览。
- 自动生成目录；标题 ID 需处理重复标题。

### 8.3 本地资源与安全

README 内容属于不可信输入：

- 默认清理原始 HTML，不执行文档脚本。
- 默认不自动加载远程图片；可以提供明确的手动加载入口或设置选项。
- 普通网页链接交给系统默认浏览器打开，并对协议做白名单校验。
- 相对图片路径以当前 README 所在目录解析，不以应用工作目录解析。
- 规范化路径并验证最终解析路径仍在允许的仓库范围内；考虑符号链接、路径穿越、大小写差异与 Windows 盘符。
- 不允许 README 通过 `file://` 或任意路径读取本机其他文件。
- 缺失图片显示局部占位符和可读错误信息，不让整篇文档失败。
- 内部 Markdown 链接可在后续版本支持，但需要校验路径和文件类型。

### 8.4 状态

| 状态 | 展示 |
|---|---|
| 加载中 | 骨架屏或简洁加载提示 |
| README 不存在 | 中性空状态，并说明搜索过哪些候选文件 |
| 读取失败 | 错误原因、重试、打开目录 |
| 图片失败 | 单图占位符、路径、重试 |
| Markdown 解析失败 | 保留原文查看入口，避免白屏 |
| 文件已修改 | 提供重新加载提示，避免悄悄覆盖阅读上下文 |

## 9. 业务状态视觉规范

状态文本和图标共同表达状态，不能只依赖颜色。

| 类型 | 语义 | 建议表现 |
|---|---|---|
| 可更新 | 远程跟踪分支有新提交，策略允许继续查看更新 | 成功/强调色徽标 + 领先数量 |
| 已同步 | 本地与远程跟踪分支一致 | 中性或绿色勾选 |
| 需确认 | 分叉、工作区风险或策略不确定 | 黄色/琥珀色徽标 + 说明 |
| 不推荐 | 远程不可用、分支不符合策略等明确原因 | 红色或中性警示徽标 + 原因 |
| 待检查 | 尚无有效结果或结果过期 | 中性徽标 |
| 检查失败 | Fetch 或读取远程信息失败 | 错误色徽标 + 重试入口 |

重要规则：

- 检查失败不等于“不推荐”。
- 远程领先不等于可以安全执行 `pull`。
- 推荐状态必须带有可追溯的原因代码和时间戳。
- 保留上一次成功结果时，应显式标记其为历史数据。

## 10. 标签与分类

标签是仓库的用户组织方式，和 Git 分支、更新状态分开管理。

- 一个仓库可以有多个标签。
- 标签建议使用浅色填充或浅边框、小圆角和 `11–12 px` 文字。
- 同一标签在列表、详情和筛选器中使用一致的颜色。
- 不要给每个标签使用高饱和颜色；默认使用中性色，用户可选少量强调色。
- 标签过多时，详情头部显示前几个，其余以 `+N` 收起；资料页可完整查看和编辑。
- 支持按标签过滤、创建、重命名、改色和删除。
- 删除标签不应删除仓库。
- 分类适合互斥的主分组；标签适合多对多的灵活标记。不要把两者合并成同一个字段。

## 11. 交互与可访问性

- 所有可交互控件具有 hover、focus、active、disabled 状态。
- 焦点边框要明显，但不应与选中行样式完全相同。
- 图标按钮应有 tooltip 和可访问名称。
- 键盘支持：上下选择仓库、Enter 打开/聚焦详情、Esc 退出多选或清除搜索、Ctrl/Cmd+F 聚焦搜索（最终快捷键需避免与文本输入冲突）。
- 动画轻量，约 `120–180 ms`；避免持续动画影响长时间使用。
- 状态不仅通过颜色区分，至少同时包含文本或图标。
- 高 DPI 下优先使用矢量图标；测试 `100% / 125% / 150%` 缩放。
- 浅色主题优先实现，设计令牌预留深色主题映射。

## 12. Tauri 实现边界

前端负责界面状态、筛选排序、标签编辑交互和展示；Tauri 后端负责受控的文件系统访问与 Git 子进程。

建议命令职责：

- `scan_repositories`：扫描授权目录。
- `get_repository_details`：获取仓库基础信息与工作区状态。
- `fetch_repository`：刷新远程跟踪信息。
- `get_update_comparison`：计算 ahead/behind 与提交差异。
- `read_repository_readme`：读取 README 原文。
- `resolve_repository_asset`：安全解析仓库内资源。
- `cancel_task`：取消仍可安全中止的任务。

实现约束：

- 不将用户路径拼接进 shell 命令字符串；使用参数数组启动进程。
- 扫描和 Fetch 使用受控并发，并提供进度、失败重试与取消。
- 对前端暴露窄接口，不开放任意文件读取或任意命令执行。
- 前端不要假定 Git 命令执行成功；始终处理超时、认证、远程不存在和非 Git 目录。
- 设计服务接口时避免直接依赖 Tauri API，以便继续使用浏览器开发环境和测试替身。

## 13. 设计验收清单

### 布局
- [ ] 三栏可调整尺寸，窄窗口时能够折叠导航。
- [ ] 列表与详情内容独立滚动。
- [ ] 当前选中仓库始终清晰可辨。
- [ ] 30–200 个仓库时筛选、排序、多选可用。

### 仓库状态
- [ ] 检查状态、同步状态、推荐结论相互独立。
- [ ] 检查失败不会被误显示为已同步或明确不推荐。
- [ ] 上次成功结果与最近尝试时间可区分。
- [ ] 每个“不推荐/需确认”结果有明确原因。

### 标签
- [ ] 仓库可设置多个标签。
- [ ] 列表、详情和侧栏筛选器标签语义一致。
- [ ] 标签可筛选、编辑和删除。
- [ ] 标签数量过多时布局不会被撑开。

### README
- [ ] Markdown 常见语法可读。
- [ ] 代码块可复制，宽表格可横向滚动。
- [ ] 相对图片路径基于 README 目录解析。
- [ ] 远程图片默认策略明确。
- [ ] 路径穿越、符号链接和不允许的协议受到限制。
- [ ] 缺失 README 与单图加载失败各自有独立状态。
- [ ] README 解析失败时仍能查看原文。

### Tauri
- [ ] 文件系统和进程能力只通过受控后端接口开放。
- [ ] Git 子进程使用参数数组，不拼接 shell 命令。
- [ ] 扫描与 Fetch 不阻塞 UI。
- [ ] 失败、取消和超时都有可见反馈。

## 14. 建议的实现优先级

1. **P0：布局与状态** — 三栏布局、仓库列表、详情面板、筛选与状态模型。
2. **P1：标签管理** — 标签显示、编辑、颜色和筛选。
3. **P1：README** — Markdown 渲染、本地图片、错误状态和安全路径解析。
4. **P2：批量任务** — Fetch 进度、并发、重试和取消。
5. **P2：提交差异** — 远程新增提交与更新前预览。
6. **P3：体验增强** — 深色主题、命令面板、键盘导航与高级筛选。

> 实施时优先保持状态语义正确和交互一致，再精修颜色与动效。本文中的尺寸和色值是设计起点，应以实际窗口、字体渲染与可访问性测试为准。
