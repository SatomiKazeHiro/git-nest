# Git Nest — 设计参考

> Git Nest 是一个面向本地 Git 仓库的桌面工具。界面优先帮助用户快速回答三个问题：
> 有哪些仓库、哪些仓库值得关注、选中的仓库发生了什么。
>
> **这份文档记的是"为什么这么做"**：设计原则、几条不肯让步的约定、以及被否掉的选项。
> 具体的类名、色值、列宽、组件结构都在代码里（`apps/web/src/index.css`、`components/`、
> `features/`），这里只指向它们，不复制——复制的那一份必然烂掉。它是设计基线，
> 不是像素规范。

## 1. 设计原则

- **桌面优先**：围绕宽屏窗口设计，窗口固定一屏、栏内滚动，不学网页的"文档滚动 + 粘性顶栏"。
- **信息密度适中**：支持约 30–200 个仓库；优先紧凑列表，而不是大卡片墙。
- **清单与详情并排，不跳页**：详情是清单区内部的第二轨，打开它不离开清单、不丢筛选与滚动位置
  （它**不是**常驻的第三栏——没选中项目时那一轨不存在，见 §7）。
- **状态优先**：更新建议、检查状态和 Git 同步状态要清晰可辨，且三者不合并（见 §9）。
- **低干扰**：大面积使用中性背景；强调色（蓝）只用于"你能点的 / 当前选中的"。
- **可恢复**：扫描、Fetch、README 读取等操作需要明确的加载、成功、空数据和失败状态。
- **安全默认**：README 与「记录」都是不可信内容；本地路径解析、外部链接和图片加载都应受控（见 §8）。

## 2. 窗口与页面结构

一个窗口 = **标题栏 + 主体**两条带（`index.css` 的 `.app` / `.body`，`layouts/AppShell.tsx`）。
标题栏只放品牌与窗口控件（`components/TitleBar.tsx`）——**导航不在那里**，页面由
`react-router` 直接切。

主体里横向怎么分栏，由各页自己排：

- **清单页**：`过滤面板 + 清单区`两列（`index.css` 的 `.split`）。清单区内部再分两轨：
  `清单表 + 详情`（`.list-scroll`），详情在选中项目时才长出来。
- **设置 / 扫描目录 / 编辑资料 / 更新报告**：都是弹窗，不占页面流
  （`store/ui.ts` 里那几个 `*Open`；"设置只有这一个界面，旧路由已删"）。

栏宽**一处定义**，不写 magic number 到组件里：过滤面板是 `.split` 的 `--w-filter`，
详情轨是 `.list-scroll` 的 `--w-detail`（`index.css`）。改宽度只改那两行；
**拖拽调宽明确不做**（理由见 [`DETAIL-OVERLAY.md`](./DETAIL-OVERLAY.md) 的「明确不做」）。

## 3. 视觉语言

- 简洁、克制、偏开发者工具风格；**白底 + 蓝主色，层次靠明度差与发丝线**，不用气氛造层次。
- 一条不变量：**蓝色 = 你能点的 / 当前选中的；四色（绿 / 琥珀 / 红 / 平灰）= git 事实。**
  蓝色不出现在"状态"和"差异"两列里——否则"哪个仓库现在要我动手"就不再是屏幕上唯一
  被颜色喊出来的东西（`index.css` 顶部的注释；`features/status/badges.tsx`）。
- **色值、字号、间距全部住在 `index.css` 的 `@theme` 里**，那是唯一来源。旧 token 名
  （`paper` / `panel` / `signal-*`）作为别名保留，新代码用语义更准的那一组。
- 可复用的具体档位（要动就动这些，别另开一档）：控件高 `h-7`（28px，按钮与单行输入框同档）、
  常规圆角 `3px`、状态药丸 `rounded-full` + `11.5px`、元信息 `11–12px`。每一对的对比度都
  在浏览器里逐对量过（`index.css` 顶部那段实测），改这几档要重量一次。
- 状态色不应成为唯一编码方式；徽标还应有文本。
- **数据位一律等宽**：分支名、路径、计数、时间（`index.css` 的 `.font-mono`）。

## 4. 过滤面板（不是"左侧导航"）

它**只在清单页存在**，是清单页自己的控件，只筛这一页的内容——设置页里没有可筛的对象，
筛选留在那儿就是个死控件（`features/projects/FilterPanel.tsx`）。所以它不叫导航，
也不放全局入口。

四段，顺序固定：

1. **我自己的**（一枚开关，与其它维度**叠加**，不互斥）；
2. **仓库状态**：全部仓库 / 可更新 / 已同步 / 不推荐 / **需要确认** / 待检查；
   —— 这六项**必须与 `Attention` 的五个取值一一对应**（外加"全部"）。少一项的后果不是
   "少一个选项"，而是那个桶既筛不出来、五项计数也加不等于「全部仓库」。`需要确认`
   （判决为 `diverged`）尤其容易被漏掉：它在服务端被单独判成 `decide`，**不会**并进
   「不推荐」——并进去会让后者失去"作者改写了历史 / 换了仓库"那层警告的分量。
3. **分类**（含"未分类"，点得动）；
4. **标签**。

约定：

- 每个入口带计数，且计数用**全量口径**（不跟着当前筛选变）——否则"可更新 12"会在你筛完
  别的东西之后悄悄换成另一个数，而它看着仍然像在报告全量。
- 选中态是浅蓝底 + 深蓝字（`bg-accent-wash text-accent-ink`），与别的可点项同一套语汇。
- **状态图标带自己的状态色，不跟着选中态走**：选中的是"我现在按这个筛"，图标说的是
  "这一桶是什么状态"，两件事不该共用一个颜色。
- 面板自己会滚：分类和标签多了只滚这一列，清单区不动。
- 设置不在面板里，是工具条右端那枚按钮打开的弹窗。

## 5. 工具条与主操作

工具条是**一行**（`features/projects/ListToolbar.tsx`）：收起/展开过滤面板 → 搜索框 →
（有筛选时）清掉筛选 → 计数 → 右侧四枚动作（联网检查更新 / 扫描目录 / 添加项目 / 设置）。

- 搜索范围是名称、本地路径、远程 URL；输入走 200ms 防抖（`ProjectsPage.tsx`）。
- 只有搜索框允许被压缩，其它控件不许（按钮被压到文字竖排是全屏最难看的一点）。
- **这里原来还有第二行**（状态 / 分组 / 排序三个下拉），已删：状态与分组各自有更好的入口
  （过滤面板，带计数、点一下筛、再点一下取消），排序挪到表头（见 §6）。删掉那一行的前提
  是表头支持"复位"——在那之前排序下拉是回到默认序的唯一入口，所以只能留着。
- **按钮没有"检查中…"态**：进度与报告都在随后打开的弹窗里，按钮继续显示"检查中…"
  会在检查早已跑完、弹窗还开着时骗人。
- 主操作是"联网检查更新"（联网那个），次操作是"扫描目录"；破坏性操作
  （移出清单、覆盖工作区等）**不得**放在常规主操作位置。

## 6. 清单表

### 6.1 行、列与排序

- **紧凑行**：行高 `40–48px`（实现取中间值 44px）。行高只有**一处来源**：`index.css`
  的 `--row-h` 与 `--row-pad-y`——历史上这两个数各改过一次、每次都只动一个，于是"改了没反应"。
- **支持按名称、状态、最近检查时间和差异排序**（分支与操作两列没有排序键——点了没反应的
  控件比没有更糟）。
- **对 30–200 个仓库，先用普通列表即可**；当实际渲染或滚动性能证明有需要时再启用虚拟列表
  ——分页 / 虚拟化 / 只读可见行那三条路与触发条件备案在
  [`LIST-SCALE.md`](./LIST-SCALE.md)。
- 五列 + 操作列（`features/projects/ProjectTable.tsx` 的 `ColumnHeader`）：

| 列 | 内容 |
|---|---|
| 仓库 | 名称 + 本地路径（两行；路径是"哪一份"的唯一凭据） |
| 当前分支 | 分离 HEAD 单独表示 |
| 状态 | 服务端算好的行动分类药丸（§9） |
| 差异 | `↓落后 / ↑领先` 两个数；"没有依据"的几种说法都在这一格 |
| 上次检查 | 最近一次**合格**检查的时间；最近一次尝试失败时挂一枚有归因的警示 |
| 操作 | 编辑资料 / 移出清单 |

- **排序 = 点表头三态循环**：第一次点得到这一列的默认方向 → 再点反向 → 第三下复位回默认序。
  三个键各有自己的默认方向，写在 core 的 `DEFAULT_SORT_DIR`（`packages/core/src/types.ts`）
  ——服务端在方向缺省时也读它，所以"点表头"和"老链接"得到同一个顺序。
- **首列钉住**：横向滚动时"仓库"那一格永远看得见（`index.css`）。
- **窄下来先丢谁**：按重要性收列——状态是唯一的行动项，**最后**才被收掉；差异（"差多少"
  是上下文，不是行动项）先走。具体档位在 `index.css` 的那几条 `@container` 里，那是唯一来源。
  基准是**清单栏自己的宽度**（容器查询），不是窗口宽度：窗口 1440 时清单栏照样可能只有
  600px，写回 `@media` 会把列压成"D:/…/…"那种断头话。

### 6.2 表里没有的东西

- **没有"同步状态"那一列**：它按设计收掉了，但**那些状态一条没丢**，并进了差异那一格
  ——少一列不等于少一句话（`features/status/badges.tsx` 的 `Diff`）。
- **没有分区行**：分类只是**排序依据**（默认序里同类连在一起），不是表的结构；
  分类是过滤面板的事，在表里再来一层就是重复。
- **没有清单级多选**：批量动作的对象是"当前筛出的全部"；要挑哪几个，是在更新报告的
  弹窗里勾的。行内自带行为的元件（链接、编辑、删除）不触发"整行打开"。
- **空状态先分清"筛没了"和"本来就空"**：这两件事的下一步动作完全不同。

行内操作按钮平时不显眼，指到这一行（或键盘焦点落在里面）才露出来。

## 7. 详情栏

- **它是清单区内部的第二轨，不是第三栏**：选中项目才长出来；打开它时清单那一轨按比例
  让位（`--w-detail = min(30rem, 45%)`：宽窗口下就是 480px，窄窗口下按比例缩，不让清单
  被挤成一条缝），清单本身、筛选与滚动位置全留着——**不跳页、不盖住清单**。
  关闭只有两条已有的路：抬头那枚"关闭"、再点当前那一行（反选）。
  **不加"点击外部关闭"，不加 Esc**。（窄到阈值以下改成浮层是另一条路，见
  [`DETAIL-OVERLAY.md`](./DETAIL-OVERLAY.md)。）
- **两个标签：概览 / README**。切换标签不改 URL；换项目时这一栏重挂载，自然回到概览。
- 抬头：名字 + 行动分类药丸 + 完整本地路径（**不截断**，允许任意位置断行）+ 三枚动作
  （编辑资料 / 联网检查更新 / 关闭）。路径是"哪一份"的唯一凭据，窄栏里该做的是让它换行，
  不是把它砍成断头话。
- 概览的顺序：状态面板（判决与原因）→ 远程 → 身份 / 分类 / 标签 chip → **记录**。
  记录是正文级字号与颜色——它是这个项目里唯一由你写的东西，不该是最不容易被读到的一块。
- 头部与标签栏固定，标签内容区独立滚动；整个窗口不跟着 README 长文一起滚。

## 8. 记录与 README：同一套 Markdown

**「记录」存的是 Markdown 原文**，读、写两侧共用同一个渲染器：

- 详情页那条只读记录按 Markdown 渲染（`features/projects/RecordView.tsx`）；
- "编辑资料"里的记录框是"编辑 / 预览"切换，预览跟着输入实时走
  （`features/projects/RecordEditor.tsx`）；
- README 也是它（`features/readme/ReadmeView.tsx`）。

三者共用 `features/readme/MarkdownBody.tsx`——**渲染器与 URL 白名单只有这一处**。
写与看必须是同一套解释，否则表现就是"我在这儿看着是这样，保存完怎么就变了"；
更要紧的是安全策略散成两处就会重演"链接拦了、图片忘了"那个洞。

已知的语义变更：老记录里本来就有 `*`、`#`、`_`、`- ` 的，现在会被当 Markdown 解释
（`*x*` 变斜体、行首 `- ` 变列表）。这是有意的，不是排版微调。

### README 阅读器

- 抬头只有文件名与大小；被截断时给"加载完整文档"按钮与一段渐变，超过上限就直说有多大
  （点了还是被截断的按钮是死控件）。
- **没有**目录（TOC）、**没有**"阅读 / 原文"切换——要那个功能得另开一轮。

### 本地资源与安全

README 与记录都属于不可信输入，判定落在 `features/readme/urlPolicy.ts`（有测试钉着）：

- 原始 HTML 一律丢掉（不渲染，也不当文本画出来）。
- 默认不自动加载远程图片：图片那一档只放行内联 `data:image/*`。
- 链接走白名单协议，放行的外链带 `target="_blank" rel="noreferrer noopener"`；
  被拦下时渲染成**不可点的普通文字**（不是点了没反应的蓝链接）。
- 相对图片路径以 README 所在目录解析，不以应用工作目录解析；规范化后验证仍在仓库范围内，
  不通过 `file://` 或任意路径读本机其它文件。
- 缺失图片显示局部占位符或 alt 文字，不让整篇文档失败。
- 内部 Markdown 链接可后续支持，但需要校验路径与文件类型。

## 9. 业务状态：三种事实分开

不能把"检查失败""远程领先""不推荐"塞进一个单一状态。它们分别描述**检查过程**、
**Git 同步关系**和**产品建议**：

- **检查过程**：最近一次尝试成没成、失败归因是什么。它和"最近一次合格检查"是两个字段
  ——失败**不刷新**新鲜度，否则断网后点一次检查，界面会显示"刚刚确认过的已是最新"。
- **Git 同步关系**：`UpdateStatus` 十三种（已是最新 / 落后 / 领先 / 分叉 / 有未提交改动 /
  没有上游 / 上游已被删 / 游离 HEAD / 没有远程 / 还没有提交 / 目录不在了 / 不是 git 仓库 /
  读不出状态），判定是 core 里那个纯函数状态机。
- **产品建议**：判决（`UpdateVerdict`）与行动分类（`Attention`）。判决在检查那一刻算出来
  并**落库**，之后原样显示——现算会拿本地 refs 里的旧结论冒充依据。清单那一列显示的是
  服务端算好的 `Attention`（可更新 / 已同步 / 不推荐 / 需要确认 / 待检查），**前端不重算**。

规则：

- 检查失败不等于"不推荐"；远程领先不等于可以安全 `pull`。
- 结论必须带有可追溯的原因与时间戳；保留上一次成功结果时，要显式标记它是历史数据
  （超过 12 小时且是远程相关的结论，措辞降级成"上次看是…"，颜色也降档）。
- **色彩政策**：绿色只给"可以安全快进"，"别拉"给红色，其余不着色——不用颜色替用户下结论。
- 判据与文案的单一来源是 `packages/core/src/types.ts` 与 `features/status/text.ts`。

## 10. 标签与分类

标签是仓库的用户组织方式，和 Git 分支、更新状态分开管理。

- 一个仓库可以有多个标签；删除标签**不动项目本身**，只把它从"N 个项目"上摘掉。
- 标签用浅色填充或浅边框、小圆角、`11–12px` 文字；同一标签在列表、详情和筛选器里
  语义一致；不要高饱和，默认中性色。
- **分类现在是一份可配置名单**（服务端的 `categories` 表），不再是编译期枚举。
  内置四个（知识库 / 备份 / 试验 / 工具）来自 core 的 `BUILTIN_CATEGORIES`：它们的 key
  就是库里 `projects.category` 已经存着的值，所以"分类可配置"不涉及任何数据迁移；
  内置项**不可改名、不可删**（服务端拒绝）。用户自己加的可以改名、改图标、删除。
- 用户给的是**显示名**，key 由服务端从名称生成并保证唯一——所以"自由文本会造出
  `backup` / `backups`"那条老顾虑仍然封着。
- 分类适合互斥的主分组；标签适合多对多的灵活标记。**不要把两者合并成同一个字段。**
- 编辑都在设置弹窗里（`features/settings/CategorySection.tsx` / `TagSection.tsx`），
  筛选在过滤面板。

## 11. 交互与可访问性

- 所有可交互控件有 hover、focus、active、disabled 状态；焦点样式与选中行样式区分
  （`index.css` 的 `:focus-visible`）。
- 图标按钮必须有 `aria-label` 与 tooltip；状态不只通过颜色表达，至少有文本。
- 键盘：Tab 可达；弹窗/弹层由 `components/Dialog.tsx` 统一负责初始焦点、Tab 圈定、
  Escape 关闭与焦点归还，**嵌套时 Escape 只关最上面那个**；下拉与图标选择器在捕获阶段
  拦 Escape，不把它漏给弹窗。
- 动画轻量（`120–180ms`）；不做"会抖"的宽度过渡。
- 高 DPI 下优先矢量图标；浅色主题优先，令牌预留深色映射。

**明确没有的**（免得再被当成现状写进设计）：清单级多选、清单里的上下键选行、`Ctrl/Cmd+F`
聚焦搜索、全局命令面板、拖拽调宽栏宽。要加就是新的一轮，别在文档里当既有约定用。

## 12. 前端与后端的边界

这一层是四块：`apps/web`（React + Vite，只渲染服务端算好的结论）、`apps/server`
（Fastify + better-sqlite3 + 调 `git` 子进程）、`packages/core`（两端共用的类型、schema、
常量）、`src-tauri`（桌面壳，只管窗口与 sidecar）。

- **文件系统与 git 全在 Node 服务里，前端只走 HTTP（`/api`）**。没有"一组 Tauri 命令"
  那回事——壳不提供 `scan_repositories` 之类的接口，它连业务逻辑都不碰。
- 接口的收口与形状见 `apps/server/src/routes/`，共用类型见 `packages/core/src/`。
- 不将用户路径拼接进 shell 命令字符串；用参数数组启动进程。
- 扫描与 Fetch 使用受控并发，并提供进度、失败重试与取消。
- 对前端暴露窄接口，不开放任意文件读取或任意命令执行。
- 前端不要假定 Git 命令执行成功；始终处理超时、认证、远程不存在和非 Git 目录。
- **前端不直接依赖 Tauri API**（`lib/desktop.ts` 就是那条边界，浏览器开发与测试替身
  都靠它）；打包形态下"API 在哪"由壳注入，见 [`src-tauri/README.md`](../src-tauri/README.md)。
- 端口只有一处定义：`packages/core/src/types.ts` 的 `DEFAULT_PORTS`，Rust 侧与配置里
  都不许再抄一遍数字。
