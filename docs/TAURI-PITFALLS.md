# 桌面壳避坑指南（Tauri 2 + 本机 HTTP 服务 + 静态前端）

适用形态：界面是打包进二进制的静态前端，数据与逻辑在本机 HTTP 服务里（Node 等
sidecar 进程），Tauri/Rust 只当壳。这份文件是**事故清单**，不是教程——每条先给
能拿去搜索的报错原文，再说根因与怎么躲。与具体项目无关，动工前扫一遍即可。

## 总原则（一条顶半份清单）

**这类架构的坑几乎只在打包/安装形态下现形。** dev 形态自带三样"假的便利"：
dev-server 代理（前端不用知道 API 在哪）、同源（没有跨源预检）、仓库里的
node_modules（依赖怎么都解析得到）。打包后三样全没。所以：

- 验证分三层，别混用：**dev**（手感/HMR，测不到壳）；**`tauri build --no-bundle`
  后直接跑 `target/release/<app>.exe`**（它的目录布局**就是**安装后的布局——
  sidecar、注入、CSP、数据落点都在这层测，日常就用这层）；**真装一次**留到最后，
  它额外验的只有打包器本身和文件落点规则。
- 前端是**编译期内嵌**进二进制的：跑 release 前必须先 build 前端，顺序错了会把
  旧产物嵌进去，变成"改了界面却没生效"的假象。

## 一、启动就死 / 数据放哪

### 1. WebView2 用户数据目录落 C 盘 → 建窗即闪退

**症状**：`Failed to setup app: ... failed to create webview: WebView2 error:
WindowsError(HRESULT(0x8000FFFF), "灾难性故障")`，exit code 101，窗口一闪就没。
（同一条死路在不同会话里也可能报 `拒绝访问 (os error 5)`——别被带偏。）

**根因**：Tauri 在 Windows 上把 webview 用户数据目录强制设为
`%LOCALAPPDATA%\<identifier>`（C 盘）。某些机器上 C 盘被安全软件/权限策略拦截，
environment 建不起来；同一目录放另一块盘（D:）就完全正常。和「运行时没装/坏了」
无关，别往那边查。

**躲法**：

- 建窗**之前** `std::env::set_var("WEBVIEW2_USER_DATA_FOLDER", …)` 指到你能控制的
  位置（WebView2 只在建 environment 那一刻读它，没有别的传参入口）。
- 探测目录可写的判据是**真的写一个文件再删**，不是看权限位、也不是看
  `create_dir_all` 成不成（目录已存在但只读时它会成功返回）。
- 数据目录策略先定死再写代码：安装目录（Program Files）对普通用户**只读**；
  「不可写就悄悄退回别处」是坑（数据跑到用户没指定的地方）。写不进就**大声失败**，
  报错里给出可操作的出路。
- 安装器选 NSIS `installMode = "currentUser"`（装到可写的 `%LOCALAPPDATA%\Programs`，
  不弹 UAC）；MSI 没有每用户选项，只能装 Program Files。
- 排查模板：同一程序，数据目录分别指到 C 盘与 D 盘各跑一次，立刻见分晓。

### 2. 启动失败时用户"点了没反应"

**症状**：双击启动，什么都没发生。

**根因**：Windows release 没有控制台（`windows_subsystem = "windows"`），
`eprintln!` 全蒸发。

**躲法**：日志**落盘**（tauri-plugin-log，文件跟着数据目录走，sidecar 的输出也
转发进去）；webview 建出来之前的死路（如数据目录不可用）除落盘外再弹一个**系统
对话框**（此刻 tauri 的 dialog 插件指望不上，用 rfd 这类纯系统对话框）。

## 二、壳与子进程（sidecar）

### 3. `\\?\` verbatim 路径害死 Node

**症状**：装出来的应用永远「后端没启动」；日志里
`Error: EISDIR: illegal operation on a directory, lstat 'D:'`，sidecar 退出码 1。

**根因**：Tauri 的 `resource_dir()` 在 Windows 上可能给出 `\\?\D:\...` 扩展长度
路径。Rust 没事，**Node 解析主模块时把它拆成 `D:`** 然后崩。

**躲法**：所有跨进程边界的路径（入口脚本、传给子进程的数据库路径、cwd）统一过
一个剥前缀函数；两种形态都要认：`\\?\D:\x` → `D:\x`，
`\\?\UNC\server\share\x` → `\\server\share\x`。给这个函数写单测，并带一条
「拿文件当目录必须失败」的反向验证。

### 4. 资源的安装落点跟你推断的不一样

**症状**：「没找到 xxx 文件——多半是打包时漏了 resources」。

**根因**：`bundle.resources` 的 glob **保留完整目录结构、不剥前缀**
（`binaries/foo/**/*` 装出来是 `<resource_dir>/binaries/foo/...`）；
而 `externalBin` 是另一套规则（剥掉 `-<target-triple>` 后缀、落在 exe 旁边）。
`--no-bundle` 的暂存目录形状有迷惑性，看它推断会推错。

**躲法**：验「装出来长什么样」看打包器生成的**权威清单**（Windows：
`target/release/wix/x64/main.wxs`；NSIS 同理看它的脚本），别靠推断。

### 5. sidecar 的输出没人读 → 服务"莫名其妙卡住"

**根因**：子进程 stdout/stderr 管道缓冲区满，进程阻塞在写日志上。

**躲法**：spawn 后必须有任务持续排空两个流并转发进壳的日志（顺带解决
「子进程的报错在双击启动时看不到」）。

### 6. 退出不杀子进程 → 下次启动 EADDRINUSE

**躲法**：`RunEvent::ExitRequested` 里统一杀；句柄用 `Mutex<Option<_>>` 装
（`kill(self)` 夺所有权，State 只给共享引用）。同类：服务端口写死时，被占只会
表现为「连不上后端」，EADDRINUSE 只在日志里——要么支持换端口（并同步改注入
前端的基地址），要么文档写明。

## 三、前端 ↔ 本机服务（这层全是"dev 看不见"的坑）

### 7. CORS 预检只放了读，写全挂

**症状**：读和 POST 正常，**只有** PATCH/PUT/DELETE 报 `net::ERR_FAILED`，
界面只说「连不上后端」。

**根因**：CORS 中间件默认 `methods` 通常只有 `GET,HEAD,POST`（@fastify/cors 就是），
不会因为你注册了 PATCH 路由自动放开。dev 走代理是同源、没有预检，**浏览器里开发
永远看不见**。

**躲法**：`methods` 显式列全；origin 白名单加上壳的页面来源（Windows 打包形态是
`http://tauri.localhost`，macOS/Linux 是 `tauri://localhost`——不覆盖连**读**都
被拦）；SSE 端点若往 `reply.raw` 手写头部，它拿不到 CORS 插件的头，要和白名单读
同一份清单。

### 8. 前端不知道 API 在哪

**症状**：打包后界面整个是空的，dev 全正常。

**根因**：`fetch('/api/...')` 是相对路径，dev 靠代理转发；打包后没有代理，
`/api` 打到 webview 自己的 origin。

**躲法**：
- 前端**一处收口**拼地址（一个 `apiUrl()` 函数），并加一条**机器闸门**：扫源码，
  裸 `/api` 字面量只许出现在收口文件里（漏一处的后果是静默的；闸门要自带
  「故意写坏的样本必须被抓到」的正对照）。EventSource/SSE 调用点最容易漏。
- 基地址由壳用 `initialization_script` 在**页面任何脚本之前**注入全局变量；
  页面拿不到注入值就退回相对路径（浏览器行为不变），注入值坏掉也一律退回。
- **别**用构建期 define 钉死端口：端口可被环境变量覆盖，钉死会制造「服务在新
  端口、前端打旧端口」且报错不提端口。

### 9. CSP 把请求/热更新挡了

**躲法**：`connect-src` 里 API 端口写**通配**（`http://127.0.0.1:*`），别钉死
（端口可覆盖，钉死会让「改端口」和「CSP 拦住」同时发生且不报原因）；
`http:` **不匹配** `ws:`——dev 的 HMR 走 websocket，不写 `ws://localhost:*`
热更新静默失效。CSP 每条都按应用**实际**加载的东西写，别抄模板多放宽。

## 四、工程方法（这批坑在"怎么验证"上）

### 10. 冒烟复刻错了形状 = 白测

两次真实教训：
- 隔离冒烟用 `%TEMP%` 下自拼的普通路径，全绿；真实安装形态给的是 verbatim
  路径——**两者恰好差在最要命的那一处**（坑 3）。
- 排查时「换到 `%TEMP%` 也没用」的结论是错的：`%TEMP%` 也在 C 盘，与对照组
  没分开变量（坑 1）。**对照实验的两组要真的只差一个变量。**

**躲法**：冒烟复刻**安装后的目录布局与路径来源**（不只是文件内容）；必须带一条
**反向对照**（抽掉随包依赖、应当失败的那条）——否则就地跑必然命中仓库根的
node_modules，"绿"什么都证明不了。

### 11. 依赖与路径的隐形假设

- workspace 软链包（`workspace:*`）打进 sidecar 必须**内联**（esbuild `--bundle`），
  运行时解析不到软链。
- 原生模块（better-sqlite3 等）保持 external，`.node` 随包拷。
- 拿传递依赖（"tsx 依赖了 esbuild 所以我能用"）当正式构建脚本 = 定时炸弹，
  转正时显式声明。
- 打包后一定会变的值（数据库路径、CORS origin、端口），dev 期就留环境变量接缝，
  别等打包时才缝。
- 配置常量只有一个来源：端口这种数，Rust 侧用 build.rs 从前端的源文件生成，
  抄成两份的后果是悄悄不一致。

### 12. 排查纪律

- **先最小复现再下结论**：一个 30 行的 wry/tao example（裸 WebView2 开窗）就能把
  「壳/代码的问题」与「机器/运行时的问题」分开——这次就是靠它把 0x8000FFFF 从
  「安全软件」「运行时坏了」一路缩到「显式数据目录 + C 盘」这个组合。
- 别顺手 `cargo clean`：全量重编十几分钟起，排查期用增量实验。
- 报错原文要读全：`os error 5` 与 `0x8000FFFF` 是同一条死路在不同会话的两种说法，
  只凭一个样本会建错假设。

## 动工前 30 秒清单

1. 数据根策略定死（放哪 / 写不进怎么办 / 安装到哪 / 安装器 per-user）；
2. `WEBVIEW2_USER_DATA_FOLDER` 建窗前设好，可写探测 = 真写文件；
3. 跨进程路径统一剥 `\\?\`（带单测）；
4. CORS `methods` 列全 + origin 白名单含壳的来源 + SSE 头部同源清单；
5. 前端 API 地址一处收口 + 壳注入基地址 + 源码闸门（含正对照）；
6. CSP `connect-src` 端口通配 + 补 `ws:`；
7. sidecar：排空输出并落盘、退出杀进程、日志文件跟数据目录走；
8. 三层验证跑通，冒烟复刻安装后布局 + 带反向对照。
