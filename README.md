# git-nest

本地 git 项目管理工具：管理自己的项目 + 追踪网上开源项目的本地克隆。
替代手写 README 项目清单——项目表 + 每个项目一段自己的记录、批量更新检测与勾选式更新。

> **接手先看 [`docs/STATUS.md`](docs/STATUS.md)**：当前进度、代码地图、核心不变量、
> 待决定的事、以及这个环境踩过的坑。
> 设计与实现差异见 [`docs/superpowers/specs/2026-06-20-git-nest-design.md`](docs/superpowers/specs/2026-06-20-git-nest-design.md) 第 13 节。

## 跑起来

```bash
pnpm install
pnpm dev          # server :5174 + web :5173
```

打开 http://localhost:5173 。

单独启动：

```bash
pnpm dev:server
pnpm dev:web
```

其他脚本：

```bash
pnpm typecheck    # 三个包一起 tsc --noEmit
pnpm test         # vitest，core / server / web 三个 project
pnpm build        # 构建 web 产物（core / server 以源码形式运行，没有构建产物）
```

首次启动会在 `data/git-nest.db` 建库（已 gitignore）。删掉这个文件就回到空清单。

## 结构

```
git-nest/
├── apps/
│   ├── server/   Fastify + better-sqlite3，REST + SSE（批量更新的进度就是 SSE）
│   └── web/      Vite + React 19 + TanStack Query + React Router + Tailwind v4
└── packages/
    └── core/     共享类型 + zod 校验 + git 执行层，前后端同一份
```

- `packages/core` 无 UI、无 HTTP 依赖，以源码形式被引用（`exports: ./src/index.ts`），改完不用构建。
- **core 有两个入口**：`@git-nest/core`（类型 + zod，浏览器安全）与 `@git-nest/core/git`
  （依赖 `node:child_process`，只能 node 侧引）。别在 barrel 里 `export *` git 层，
  否则浏览器打包会报 `node:child_process has been externalized`。
  （`exports` 里曾经还挂着一个 `./types`，全仓零引用，已删——留着死入口只会让人猜「该从哪个进」。）
- 元数据进 SQLite；git 实时状态不落库，每次现查（server 侧 3 秒短缓存，`?fresh=true` 可绕开）。
- 本地绝对路径只存在本机 SQLite 里，不进任何会被提交的文件。

### 窗口骨架

界面是按**桌面软件**排的，不是按网页排的。根节点锁死不滚，滚动只发生在某一栏里面：

```
┌──────────────────────────────────────────────────────────────┐
│ git-nest · 本地仓库清单                              (窗口控件) │ 标题栏
├──────────────────────────────────────────────────────────────┤
│ 文件  编辑  视图  工具                                        │ 菜单栏
├──┬────────┬──────────────────────────┬────────────────────────┤
│≡ │我自己的 │ 搜索…  联网检查更新  +添加 │ 项目详情（常驻）        │ ← 清单页
│⚙│ 分类   │──────────────────────────│                        │
│  │ 标签   │ 清单表（工具条固定、表自滚）│                      │
├──┴────────┴──────────────────────────┴────────────────────────┤
│ 已选 2 个                        ↑↓ Space Enter Delete       │ 状态栏
└──────────────────────────────────────────────────────────────┘

活动栏 48px │ 过滤面板 168px │ 清单（至少 412） │ 详情 480
     ↑ 只有页面              ↑ 只在清单页
```

**「侧栏」与「过滤面板」是两样东西**，不是同一个东西分成两段：

- **活动栏**（48px 图标栏，VS Code 活动栏那种）里**每一项都是一个页面**——
  清单、设置，将来还有别的。点它换一页，所以是图标；窄到 60px 之后
  文字放不下，而 `aria-label` 与 `title` 让读屏与鼠标悬停都拿得到名字。
  清单只是其中一项——将来加页面就是加一个图标，不占横向空间。
- **过滤面板**（`features/projects/FilterPanel.tsx`）是**清单页自己的控件**——
  我自己的 / 分类 / 标签，点了只筛眼前这张表，不换页。

混在一列里的坏处很具体：「分类」长得像个能点过去的页面，点了却什么都不换，
那种落差最难察觉。分成两列之后「属于哪儿」不用解释了。设置页那一栏只有
活动栏与内容——筛选在那里没有对象可筛（死控件比消失更糟：点了没反应，
用户只会觉得这个应用卡了）。

- **`/` 与 `/projects/:id` 是同一个布局路由的两条路径**，区别只在右边那栏有没有内容。
  深链、前进后退、书签都照旧有效；「正在看哪个项目」住在 URL 里。
- **收列断点看的是清单栏自己的宽度**（`@container`），不是窗口宽度——三栏之后
  视口宽窄和「表格有多宽」已经没有任何关系了。
- **加速键只有一份来源**（`apps/web/src/lib/keys.ts`），行为全经
  `lib/commands.ts` 的注册表，菜单栏与快捷键走同一条路。弹窗打开时全局快捷键
  整个让位；焦点在输入框里时 Ctrl+A 之类让位；**没人接手的组合键不拦**，
  浏览器自己的 Ctrl+R 照常工作。
- 窗口控件与拖拽区只在真的跑在桌面窗口里时才出现（读 `window.__TAURI__`，
  见 `lib/desktop.ts`，**没有引 Tauri 依赖**）。浏览器里开发时它们是藏起来的。

### 窗口最小宽度：1150

**打包时把窗口最小宽度设成 1150×720**（Tauri 里是逻辑像素）。这个数是量出来的，
不是拍的，来源是「清单那一列至少要 412px 才保得住 **名称 / 落后 / 推荐** 三列」：

```
活动栏 48 + 过滤面板 168 + 清单最少 412 + 详情 480 = 1108  →  取 1150
```

低于它清单列就压到 412 以下，三列保不住。**一个守不住的下限比没有下限更糟**——
它让人以为再拖一点也许行。

| 宽度 | 清单列 | 结论 |
|---|---|---|
| 1440 | 732 | 很宽 |
| 1280 | 572 | 可用 |
| 1150 | 412 | 下限 |
| 1100 | 344 | 不够，三列保不住 |

**分屏救不了**：1440 的屏幕左边开这个应用、右边开编辑器，应用宽度就是 700。
本轮**没有**为窄窗口做降级（详情栏变抽屉之类），所以分屏时界面确实会挤——
这是已知的取舍，不是忘了。

设置页是**固定宽度的内容块**（`.settings-body`，46rem = 736px，水平居中），不是
会伸缩的流式盒子。所以它内部的两列在任何窗口宽度下都长得一模一样，窗口变宽只是
多了留白。1150 时内容区 1102，放下 736 还余 366px——这也是上面那个下限成立的原因。

顺带一个好处：这块内容是**自包含**的，将来真要做「设置弹窗」而不是整页路由，
把它整体抬进一个 ≥46rem 宽的面板即可，不用重新排版。

**这一层解决不了分屏。** 1440 的屏幕左边开这个应用、右边开编辑器，应用宽度就是
700，Tauri 的 `minWidth` 管不着。本轮**没有**为窄窗口做降级（详情栏变抽屉之类），
所以分屏时界面确实会挤——这是已知的取舍，不是忘了。装好之后如果实际用着别扭，
再加那层降级。



## 「我自己的项目」与「分类」

这是两件**互不相关**的事，以前被混成了一件，所以别扭。

### 我自己的项目（一个勾选框）

**「这是我自己写的项目」是项目上的一个真布尔**（`projects.is_own`，界面上的
勾选框在「编辑资料」里）。批量检查**默认跳过**它们——自己的项目自己清楚，
没必要让它们去联网问远程。

要在批量里带上，去设置里打开「自己的项目也参与检查」。

> **它曾经是「分类正好等于 personal」。** 那是一条挂在自由文本上的隐藏规则：
> 写成 `Personal`、多打一个空格、或者干脆写成中文，那几个仓库就静默回到
> 「会被联网检查」的状态，**界面上没有任何提示**。一个只有布尔含义的东西，
> 就该用布尔来存；规则不该挂在人会拼错的字符串上。

### 分类（一个枚举）

每个项目属于**一个**分类，回答「这个仓库在我的生活里是什么角色」。
它是一个**枚举**，能选的就这么几个，界面上是一排可点的 chip：

| 存的值 | 界面显示 |
|---|---|
| `''`（空） | 未分类 |
| `knowledge-base` | 知识库 |
| `backups` | 备份 |
| `experiments` | 试验 |
| `tools` | 工具 |

**分类不带任何行为**，只管分组与筛选。**存进数据库的永远是英文**，界面上给人看
中文——映射表在 `packages/core/src/types.ts` 的 `CATEGORY_LABELS`，是全覆盖的
（枚举之外的值进不了库）。

**`personal` 已经不在里面了。** 「是不是我自己的」是 `projects.is_own` 那个
勾选框。分类里再留一个 personal 只会诱导人把同一件事记在一个**不起作用**的地方
——而且以前填了它**真的**会被批量检查跳过，现在不会了，凭记忆填的人会看到分类里
明明写着 personal 却没拿到期待的行为。

**加一个分类 = 改 `types.ts` 的 `CATEGORIES` 一个常量**（前后端共用），就这一处。
这是有意的：现在不留「将来可能要自定义」的口子，等真的需要时再拆。

**「未分类」不是分类，是「没有分类」**，所以两处都不列它：

- 过滤面板里不列——点它筛不出任何东西（它本来就是筛完之后剩下的），
  要看它们把筛选清掉即可
- 编辑弹窗里不列——列了会被**预选中**，看起来像「你选了未分类」，
  其实只是什么都没选，白占一个高亮位

两处都是**开关语义**：点一下选中，再点一下取消（回到没有分类）。
过滤面板那一项靠 `setCategory` 本来就有的开关逻辑（同值再点一次置 null）。

**唯一要知道的代价**：枚举之外的老值会让那个项目**存不回来**（校验会被拒）。
当前库里没有这种值，所以当下零成本；将来真出现了，按项目自己的规矩（不变量 14）
删开发库重建即可。

**别和「标签」混起来**：分类**一个**，回答「它是什么」；标签**可以有多个**，回答
「它涉及哪些主题」。

### 能在哪儿配

| 地方 | 能做什么 |
|---|---|
| 编辑项目弹窗 | 勾「这是我自己写的项目」、**选**分类（枚举 chip）、填标签、写记录 |
| 过滤面板「我自己的」 | 按这个布尔筛清单（**只有勾过至少一个才出现这一项**） |
| 设置 → 联网检查与更新 | 自己的项目要不要参与批量检查 |
| 其它地方（清单表、详情栏） | **只读展示** |

清单表里自己的项目**名称前面有一枚小记号**（不另开一列——表已经九列了，
而这一条信息只值一枚记号）。它用图标不用圆点：清单里已经有一列用颜色编码
git 事实（落后 / 推荐），再来一个圆点会让人以为是某种状态；而且它是灰色的，
因为「我自己的」是你自己的标注，不是 git 报出来的事实，不该穿信号色。

过滤面板里那一项**与分类 / 标签叠加**，不是互斥的——「我的 tools」是一个合理的查询，
所以点它不会把分类清掉。（分类与标签之间仍然是互斥的：它们是同一层的两种分组方式。）
筛选在**服务端**做（`GET /api/projects?own=1`），不是拉全量再前端过滤。

### 两条不影响行为的事实

- 清单里的行**按分类排序**（同类的挨着，没分类的排最后），但**表里不画分类分区行**
- **扫描导入的项目分类一律留空、`我自己的` 一律不勾**——程序不猜你这是备份还是工具

## git 执行层的硬规则

全部实现在 `packages/core/src/git/`，照抄 `.reference/github-kb` 的安全规则：

1. 每次调用都带 `GIT_TERMINAL_PROMPT=0` + `credential.interactive=false` + `credential.helper=`，
   单命令硬超时（默认 120s，在设置页改；见下面「超时怎么调」）
2. 用 `execFile` + argv 传参，不走 shell；仓库目录用 `git -C <dir>` 而不是 spawn 的 cwd
   （cwd 走 OS 的 SetCurrentDirectory，路径过长会直接 spawn 失败）
3. **同仓库串行、跨仓库并发上限 4**（`Scheduler`），防 `index.lock` 冲突与远程限流
4. 探测命令逐个执行、单独判退出码：「没有上游」「detached HEAD」是预期内的非零退出
5. `pull` 只允许 `--ff-only`；脏工作区 / detached / 无上游 / 已分叉一律跳过并说清原因
6. **更新前先比基线**：`pull` 会先 `fetch` 一次（只动 `refs/remotes/*`，不碰工作区），
   拿「上次见到的上游 SHA」跟新上游比——那个提交不在新历史里就是作者改写过历史，
   直接拒绝，连 `--ff-only` 都不发。这一步必须在 fetch 之前读基线（不变量 10），
   所以顺序是「先 fetch → 比对 → 才动工作区」
7. 失败按 网络 / 认证 / 锁残留 / 路径过长 / 目录丢失 归因，各自给可操作的提示；
   「远程仓库找不到」单独说，不当成「要认证」——那会把人引向错误的方向。
   注意「路径太长」和「目录没了」报的是同一句 git 报错
   （`cannot change to '<dir>': No such file or directory`），判据只能是那个路径本身的长度

状态机覆盖的常态分支（不是异常）：`up_to_date` `behind` `ahead` `diverged` `dirty`
`no_upstream` `gone` `detached` `no_remote` `no_commits` `missing` `not_a_repo`，
外加一个 `error`（读不出来，比如路径过长或 git 起不来）。完整定义见
`packages/core/src/git/types.ts` 的 `UpdateStatus`。

**状态措辞按新鲜度降级。** 状态接口只读本地 refs、从不联网，所以「已是最新」在
没有依据时是失真的：远程相关的结论（最新/落后/领先/分叉）要看「什么时候查过」——
从没查过时 `up_to_date` 退成「没查过远程」且不给颜色；但 `behind`/`ahead`/`diverged`
的**方向和数字照常显示**（它们来自本地 refs，本身可靠），只标注「本地看到的，没联网确认」。
超过 12 小时把「已是最新」降级成「上次看是最新」。纯本地状态（脏 / 游离 / 没有远程）
任何时候都可信，不受影响。

## 自动 fetch 与命令日志

服务启动 30 秒后自动跑一轮 fetch，之后每 30 分钟一轮。它让「落后多少 / 推不推荐更新」
的数字保持新鲜——否则新加的仓库在你手动检查前推荐列一直是空的。

**它只更新 `refs/remotes/*`：不 pull、不快进、不碰工作区**，「绝不自动更新」那条不变量
仍然成立。**自己写的项目**默认跳过（跟设置页那个开关走）。跨仓库并发走设置里那个上限
（和手动检查同一个 `Scheduler`），所以仓库多的时候不会一条条串行等。

**`update_checks` 有上限**：每个项目只保留最近 2000 条检查历史（一轮自动 fetch 就是
每个仓库一行，不设上限这张表会一直长）。清理在每轮批量任务收尾时做。

**每一条 git 命令都记进命令日志**（设置页 →「自动 fetch 与命令日志」→ 看命令日志，
或 `GET /api/commands`）：时间、发起者（`auto-fetch` / `check` / `status` / `pull`）、
完整实参、仓库目录、退出码、耗时。日志在内存里，最近 1000 条，重启清空——
它是排查工具，不是审计系统。

## 推不推荐更新（一阶段最要紧的一条）

清单页有「推荐」一列，详情页有完整理由。它回答的不是「落后几个」，而是
**拉了会不会出事**——尤其是用户点名要防的「作者删库 / 重置仓库」：

| 判决 | 什么情况 | 显示 |
|---|---|---|
| `safe` | 本地 HEAD 是上游的祖先 | 可更新（能快进） |
| `diverged` | 两边都有提交，但有共同祖先 | 要你决定 |
| `rewritten` | 上次见到的上游提交**不再**在上游历史里 | **别拉**（作者 force push 了） |
| `unrelated` | 两个历史**没有共同祖先** | **别拉**（作者多半删库重建了） |

判据是 `git merge-base --is-ancestor` 的退出码（0=是祖先 / 1=不是 / 其它=出错），
实现在 `packages/core/src/git/inspect/recommend.ts`，行为表在
`packages/core/test/git/recommend.test.ts`（9 个真实仓库场景）。

**一个诚实的限制**：作者 force push 掉「本地从没读到过」的提交，是**看不出来**的
——那种情况本地 HEAD 仍是新历史的祖先，git 自己也会正常快进。要抓住它只能靠基线
（上次见到的上游 SHA），而基线需要检查过一次才有。这个限制有一条专门的用例钉着。

**更新那一步也拿基线兜了一道**（2026-10 补）：调用方手上那道闸读的是「上次检查的结论」，
而「检查」到「点更新」之间作者可能刚好 force push。所以 `pullRepo` 自己也收基线：
先 fetch（只动 `refs/remotes/*`）、比对、确认没被改写才动工作区。行为表见
`packages/core/test/git/pull.test.ts` 的「基线闸」一组。

结论**只在真正检查过之后才产生**，并随检查结果落库（`update_checks.detail`）；
清单页显示的是那次结论，不是现算的——现算要先 fetch，而列表是纯本地读。
没查过就显示「没查过」，绝不给绿色的「可更新」。

## API

方法逐条写清（别写成 `GET/POST/PUT/DELETE /api/tags` 那种——实际每个路径支持的方法
并不一样，照着写客户端会 404）。`apps/server/test/docs-api-drift.test.ts` 会拿这段
和源码里真实注册的路由对账，写错了测试就红。

```
GET    /api/health

GET    /api/projects?category=&tag=&q=&own=
                                   （own=1 只看我自己的；与 category/tag **叠加**，
```

**批量上限只有一份来源**：`packages/core/src/limits.ts`（`MAX_STATUS_IDS` 200 /
`MAX_BATCH_IDS` 1000 / `MAX_SCAN_RESULTS` 500）。服务端按它校验，**前端也读它**——
状态那一列按 200 自动分块、检查面板超过 1000 提前说清并禁用按钮、扫描与导入共用
500。这些数字原来散在五处、前端一个都不知道，于是项目超过 200 个时列表页的状态列
会静默变成「读状态…」，批量动作只回一句「参数有误」。

**超时怎么调**：没有 `GIT_NEST_GIT_TIMEOUT` 这个环境变量——超时是设置表里的
`gitTimeoutMs`（默认 120s，允许 1s–600s），在设置页改，或 `PATCH /api/settings`。
数字字段是「失焦或回车才提交」，不是每敲一个字发一次请求。
代码真正读的环境变量只有这几个：

| 变量 | 用途 | 默认 |
|---|---|---|
| `GIT_NEST_DB` | SQLite 文件位置 | `data/git-nest.db` |
| `GIT_NEST_PORT` | server 端口 | `5174` |
| `GIT_NEST_HOST` | server 监听地址 | `127.0.0.1`（**改成 `0.0.0.0` 等于把接口开放给整个局域网**，没有任何鉴权；启动时会打一条警告日志） |
| `GIT_NEST_CORS` | 允许的跨域来源（同时是**写接口的 Origin 白名单**） | `http://localhost:5173` |
| `GIT_NEST_TAURI_ORIGIN` | 额外放行的桌面端来源（逗号分隔） | `tauri://localhost,http://tauri.localhost,https://tauri.localhost`（配成空串可整个关掉） |
| `GIT_NEST_API` | web 开发服务器的 API 代理目标 | `http://127.0.0.1:5174` |

**写接口有一道跨站闸**：`POST/PUT/PATCH/DELETE` 带 `Origin` 且不在白名单里 → 403。
理由是这类接口都是「简单请求」（无 body、无自定义头）就能打的，CORS 只挡得住读响应、
挡不住副作用（比如 `POST /api/auto-fetch` 让全部仓库联网）。curl / 脚本不带 `Origin`，
照常能用。

**白名单里那三个 tauri 来源是给「装成桌面软件之后」准备的。** 打包之后 webview
自己起一个来源，不再是 `http://localhost:5173`；不加进来的话，添加项目、勾选更新、
改设置**全部 403**，而本地开发一路绿灯——这类只在打包后现形的故障最难查，所以提前
写进配置。放它们是安全的：这些 scheme 浏览器里的普通网页拿不到，而 `Origin` 由浏览器
按页面自己的来源填、脚本伪造不了，等于只认「我们自己那个窗口」。

更新任务为什么是「POST 启动 + GET 订阅」：`EventSource` 只能发 GET，而批量检查可能要联网
fetch 十几个仓库，不能让一个 HTTP 请求一直挂着。任务状态放内存（半小时 TTL，**只清已结束的任务**），
进度事件用「缓冲数组 + 游标」而不是发布订阅——前端拿到 id 再开连接是常态，缓冲保证不丢事件。

## 踩过的坑

- **`-c credential.helper=` 是必须的。** 只设 `GIT_TERMINAL_PROMPT=0` 不够：遇到要密码的
  远程时 git 会卡在凭证链上（实测挂 8 秒以上无任何输出），一个私有仓库就能把整个批量检查
  拖到超时。清空 helper 之后它立即报 `unable to get password from user`。
- **长路径**：实测 258 字符的目录**存在**，但 `git -C <它>` 直接 `fatal: cannot change to
  ...: No such file or directory`（exit 128），带 `core.longpaths=true` 也一样 ——
  那个选项救不了最初的 chdir。这类仓库现在直接报 `path_too_long`（门槛取 240 字符，
  比 MAX_PATH 约 260 保守一截）并说清怎么办，而不是含糊地说「不是 git 仓库」。
- `better-sqlite3` 需要跑安装脚本。pnpm 10+ 默认拦截，已在 `pnpm-workspace.yaml` 的
  `allowBuilds` 里放行（**pnpm 12 的键名是 `allowBuilds`**；pnpm 10/11 时代叫
  `onlyBuiltDependencies`，旧键在 12 里已被合并、写了不生效）；换机器后报
  `ERR_PNPM_IGNORED_BUILDS` 就跑 `pnpm approve-builds --all`。
- pnpm 12 偶尔会把 `node_modules/.pnpm/` 里的软链指到不存在的目录，表现为某个包的
  `node_modules/.bin` 里少了命令。`pnpm dedupe` 能修好。
- `pullRepo` 的前置检查只用本地事实（不是仓库 / 空仓库 / 脏 / detached），
  **不拿旧的 ahead/behind 去判「没东西可拉」**——那个数字来自上次 fetch，会把真有更新的仓库
  误报成「已是最新」。拉取交给 `pull --ff-only` 自己 fetch，失败后再用新 refs 判分叉。
- 停后台服务要按端口找 PID 再杀：`netstat -ano | grep :5174`。**别用 `taskkill /IM node.exe`**，
  会把跑着 agent 的 node 一起杀掉。
- `Scheduler.schedule` 不会重入：不要在已排队的任务里再对同一个仓库 key 调 `schedule`，
  会自锁。core 的 `getRepoStatus` / `analyzeUpdates` / `pullRepo` 内部都自己排队，调用方
  直接 `Promise.all` 就行，限流交给它们。
